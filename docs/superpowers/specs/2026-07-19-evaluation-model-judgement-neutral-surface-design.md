# 评估子模型判断摘要中性化设计

## 背景

模型评估页的每张子模型详情都包含同语义的“判断”摘要。当前摘要边框、背景和“判断”标签从 `--model-accent` 取色，因此“近期序列”会继承 Markov 的琥珀色。琥珀同时属于产品的警告色家族，容易让用户把普通模型说明误读成冷却异常、低权重或需要处理的状态。

模型身份已经由模型名称、详情内容和数据图形表达。“判断”摘要本身只负责解释模型如何得出当前结论，不承担模型状态或告警职责。

## 目标

- 所有子模型的“判断”摘要使用同一套中性表面语言。
- 让琥珀、绿色和其他语义色只在真实状态或数据图形中出现。
- 保留各模型现有图表、时间带、惩罚条和路径图形的身份色。
- 保持现有布局、圆角、间距、文案、模型逻辑和交互不变。
- 浅色与深色主题使用等价的中性层级。

## 非目标

- 不调整子模型权重、命中率、Loss、排序或状态判断。
- 不修改 Markov、Bayes、规则、窗口或上下文图形的颜色映射。
- 不改变“判断”摘要的 DOM 结构、字号、字重、圆角或内边距。
- 不修改 API、数据库、评估数据结构或滚动锚点行为。
- 不借本次修改重构整个评估页配色。

## 设计决策

### 判断摘要

`.model-judgement-summary` 不再引用 `--model-accent`。

浅色主题使用：

- 中性近白背景，与现有 `#f7f9fb` 评估说明表面保持一致。
- `1px` 冷灰完整边框，使用现有柔边界层级。
- 正文继续使用当前深灰正文色。

深色主题使用：

- 现有暗色次级表面。
- 低对比冷灰完整边框。
- 当前暗色说明文字色。

摘要尺寸、两列网格、`10px` 圆角、`8px 10px` 内边距和行高保持不变，确保纯颜色调整不会引起详情高度、滚动锚点或响应式布局变化。

### “判断”标签

`.model-judgement-label` 改为中性文字色，不再引用 `--model-accent`。

标签继续通过固定文案、600 字重、较小字号和独立列建立阅读入口，不新增色点、图标、侧边条或模型徽标。模型名称已经出现在摘要行和详情上下文中，额外身份标记会重复信息。

### 模型色与状态色边界

模型色继续用于真实的数据表达，包括：

- Markov 最近序列、重复计数和惩罚图形。
- Bayes Exact / Wildcard 路径。
- 规则偏差图形。
- 周期窗口与分组数据图形。
- 上下文观测数据图形。

真实状态继续由现有状态标签表达：

- 主导。
- 参与中。
- 低权重。
- 未启用。

本次不改变这些状态的计算、文案或颜色。判断摘要不随模型身份、权重或状态切换颜色。

## 实现边界

修改限定在：

- `WuwaFrontend/src/styles/features/evaluation.css`
- 对应的前端静态设计守卫或评估组件测试
- 本设计成为长期事实后需要同步的视觉规范与实施记录

Vue 模板无需修改。不得新增全局 UI token，除非实现时发现现有中性色无法表达批准效果；优先复用现有 `--surface-soft`、`--hairline-soft`、`--steel`、`--ink` 等语义入口或保持当前已批准的中性色值。

## 验证

### 自动验证

- 新增失败优先的静态断言，确认 `.model-judgement-summary` 和 `.model-judgement-label` 不再引用 `--model-accent`。
- 确认判断摘要仍保留完整边框、两列布局和现有几何。
- 运行评估组件相关测试。
- 运行前端全量测试和生产构建。
- 运行 `git diff --check`。

### 视觉验证

在已有登录业务数据的评估页核对：

- 浅色主题下至少展开 Markov 与另一子模型，两个判断摘要的背景、边框和标签颜色一致。
- 深色主题下重复同一对比，摘要保持中性且正文清楚可读。
- Markov 时间带、惩罚条等数据图形仍保留原有琥珀身份色。
- 主导、参与中、低权重和未启用状态仍由原有标签表达。
- 桌面与窄屏下判断摘要没有高度变化、文字裁切或横向溢出。
- 展开与收起后的滚动锚点行为没有变化。

## 验收标准

- 所有子模型判断摘要使用同一套中性表面和标签色。
- Markov 判断摘要不再呈现琥珀底色、琥珀边框或琥珀“判断”标签。
- 模型数据图形的颜色保持不变。
- 真实状态语义和业务逻辑保持不变。
- 浅色、深色和响应式布局均无视觉或交互回归。
