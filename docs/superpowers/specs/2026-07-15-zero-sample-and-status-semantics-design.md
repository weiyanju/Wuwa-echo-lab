# Zero Sample And Status Semantics Design

**Date:** 2026-07-15

**Status:** Approved for implementation

**Scope:** Wuwa Web 全局摘要、工作台、统计诊断、模型评估、浮动历史面板

**Related:** `DESIGN.md`、`docs/product-interface-principles.md`、`docs/web-ui-design-system-v2.md`、`docs/web-workbench-ui-guidelines.md`、`docs/superpowers/specs/2026-07-15-statistics-diagnosis-summary-design.md`

---

## 1. 目标

为新绑定且尚无副词条样本的用户建立一套统一、可操作、不会伪造结论的初始体验，并收口统计诊断与模型评估目前互相冲突的状态文案。

本设计解决四个问题：

1. 同一个样本量在统计页显示“起步观察”，在评估页却显示“观察中”或“样本不足”，用户无法判断这些词是不是同一件事。
2. 零样本时，真实计数、未计算指标、阶段信息和系统默认参数混在一起，容易把 `0`、`低` 或“样本不足”误读成真实结论。
3. 统计页和评估页在没有结果时仍渲染完整图表或模型模块，形成大量 `0.00%`、`0.00pp` 和“样本不足”的噪音。
4. 工作台已经可以录入第一条数据，但缺少一条足够轻量的首次使用指引，空历史面板也会占据不必要的空间。

## 2. 非目标

- 不修改统计、预测或评估算法。
- 不修改 Django API 响应结构、数据库或样本阶段阈值。
- 不增加阻塞式 onboarding、弹窗向导或强制“开始”按钮。
- 不伪造演示数据，不在零样本页面展示模拟图表。
- 不重新设计已有样本时已经确认的统计任务卡和评估任务卡。
- 不把工作台、统计和评估改成新的应用外壳。

## 3. 统一状态模型

### 3.1 样本成熟度

全局页头状态只表达“当前个人样本处于哪个成熟阶段”，统计和评估必须使用同一映射：

| 总样本数 | key | 可见文案 | 视觉语气 |
|---:|---|---|---|
| `0` | `empty` | `待录入` | 中性胶囊，无绿色状态点 |
| `1–499` | `recording` | `起步观察` | 预测绿状态胶囊 |
| `500–2999` | `initial` | `初步观察` | 预测绿状态胶囊 |
| `3000–9999` | `reference` | `可作参考` | 预测绿状态胶囊 |
| `10000–49999` | `stable` | `稳定观察` | 预测绿状态胶囊 |
| `50000+` | `optimized` | `可优化权重` | 预测绿状态胶囊 |

`待录入` 是数据状态，不是错误，也不是成功。它不得带绿色状态点。绿色状态只说明已经进入个人样本观察阶段，不表示模型正确或任务完成。

### 3.2 模型评估准备度

模型评估准备度与样本成熟度是两个不同维度，不再竞争同一个页头状态位置：

| 条件 | key | 页内呈现 |
|---|---|---|
| `evaluated_count = 0` 且评估未 ready | `empty` | “模型评估将在积累有效历史后开启” |
| `1 <= evaluated_count < 20` 且评估未 ready | `collecting` | “回测准备中”与 `evaluated_count / 20` |
| `evaluation.status === 'ready'` | `ready` | 渲染完整核心回测、融合权重和子模型回测 |

页头第一个胶囊仍显示统一样本成熟度；“回测准备中”只出现在评估页正文准备面板内。这样用户能同时知道“个人样本处于什么阶段”和“评估结果是否已经可用”。

### 3.3 样本阶段

样本阶段是已知系统规则，零样本时仍显示真实范围：

- `0–500 条`
- `500–3000 条`
- `3000–10000 条`
- `10000–50000 条`
- `50000+ 条`

显示层统一使用半角数字、en dash `–` 和 `条`；阶段规则来自现有 `sampleStageDefinitions`，不从不同页面各自切割后端中文标签。

## 4. 零样本字段显示规则

### 4.1 真实计数显示 `0`

已经有明确计数语义、且后端真实返回零的字段显示 `0`：

- 历史声骸数量。
- 总样本数量。
- 已评估样本数量。
- 当前声骸录入进度，例如 `0 / 5`。
- 统计阶段进度，例如 `0 / 500`。
- 评估准备进度，例如 `0 / 20`。

不得把这些真实零值替换成 `--`。

### 4.2 尚未计算的指标显示 `--`

没有个人样本或尚未形成评估结果时，下列指标显示两个半角连字符 `--`：

- 全局摘要中的置信度。
- 首选、前三、前五命中率。
- Log Loss。
- Brier Score。
- 统计偏差值。
- 其他依赖实际样本计算的概率质量指标。

明确约束：全局摘要的零样本置信度显示 `--`，不显示“未建立”、`低`、`0%` 或 `0.00%`。

`--` 使用数据字体、`tabular-nums`、次级文字色和稳定宽度；不得附带 `%`、`pp`、`条`等单位，不使用绿色、琥珀或红色强调。可访问名称必须说明具体指标尚未形成，例如“置信度尚未形成”“前三命中率尚未形成”。

### 4.3 语义状态显示文字

状态字段使用可理解的短文案，不使用 `--`：

- `待录入`
- `起步观察`
- `回测准备中`
- `规则基线`
- `加载失败`

语义状态与数值占位不得互相替代。

### 4.4 已知系统参数显示真实值

不依赖个人样本的系统默认值可以显示真实值，但必须明确来源：

- 规则基线概率可以继续显示，并标注“规则基线 · 尚未使用个人样本”。
- 基础融合权重如果需要展示，必须标注“基础权重”，不得写成“当前个人权重”。
- 动态调整、偏差、命中率和校准指标在形成前保持隐藏或显示 `--`。

### 4.5 集合与图表不堆占位

没有真实数据的列表、分布图和诊断模块不渲染一排 `0` 或 `--`。它们应整体隐藏，由一个行动导向的准备面板替代。

### 4.6 加载与错误不是零样本

状态优先级固定为：

1. `loading`：骨架或加载说明。
2. `error`：错误说明与“重新加载”动作；如果已有上一次成功数据，保留旧数据并标记刷新失败。
3. `ready + total = 0`：本设计的零样本状态。
4. `ready + total > 0`：正常页面。

`--` 不得用于加载或错误。只有请求已经成功，且字段按业务规则尚未形成时才显示 `--`。

## 5. 全局外壳

### 5.1 摘要值

零样本时保持三个原有摘要位置和模型评估现有视觉密度：

| 字段 | 显示 |
|---|---|
| 历史声骸 | `0` |
| 总样本 | `0` |
| 置信度 | `--` |

不增加第四个初始化指标，不为 `--` 增加解释长句。用户通过进入工作台理解下一步。

### 5.2 导航

“工作台 / 统计 / 评估”始终可进入。统计和评估的零样本页面本身承担解释与返回工作台的动作，不禁用导航，也不通过 tooltip 隐藏原因。

### 5.3 会话增量

零增量不显示 `+0`。只有本次会话真实新增声骸或样本时才显示增量角标。

## 6. 工作台零样本设计

### 6.1 保持可操作工作台

沿用现有自动创建空草稿的机制。空草稿不计入历史声骸数量，不改变现有 `0/5` 配置行为。

不新增阻塞弹窗、整页空状态或额外确认步骤。首次用户进入后可以直接检查默认配置并点击第一条副词条档位。

### 6.2 首次录入提示

在“初始化声骸”标题说明位置显示紧凑的内联提示：

> **首次录入**  检查套装、COST 和主词条，然后点击实际出现的第一条副词条数值。

提示只在总样本为 `0` 时出现；一旦产生第一条样本，恢复现有简短说明。它使用轻量背景或 1px 边界，不单独形成大卡片，不提高页面总高度。

### 6.3 预测来源

零样本下如果现有预测接口已经返回候选概率，继续展示真实规则概率，并在预测区域加入：

> 规则基线 · 尚未使用个人样本

它说明来源，不把概率伪装成个人模型结论。全局置信度仍为 `--`。

### 6.4 历史面板

当可见历史为 `0` 且本地没有明确的最小化偏好时，浮动历史面板默认最小化。已经保存的 `true` 或 `false` 用户偏好优先，不因零样本强制覆盖。

## 7. 统计诊断零样本设计

### 7.1 页头

零样本页头保持与模型评估一致的紧凑结构：

- 标题：`统计诊断`
- 说明：`尚无样本。录入第一条副词条后开始生成个人分布。`
- 状态胶囊：`待录入`，中性，无绿色点。
- 阶段胶囊：`阶段 0–500 条`。

### 7.2 准备面板

正文只显示一张扁平准备面板：

- 标题：`从第一条样本开始建立统计诊断`
- 说明：`录入一条副词条后即可查看实际分布；达到 500 条后进入总体偏差阶段。`
- 进度：`0 / 500`
- 当前来源：`规则基线主导`
- 完整样本阶段轴。
- 主动作：`去工作台录入第一条`

这张面板复用已有阶段轴，不增加卡片套卡片。

### 7.3 隐藏无意义结果

总样本为 `0` 时不渲染“副词条分布偏差”任务卡，不显示：

- 当前偏高 / 当前偏低。
- `0.00%` 观察率。
- `+0.00pp` 偏差。
- 13 条空副词条分布行。

从第一条真实样本开始恢复现有统计任务卡结构，成熟度切换为“起步观察”。

## 8. 模型评估零样本与准备中设计

### 8.1 页头

在评估未 ready 时：

- 第一胶囊：统一样本成熟度，零样本为 `待录入`。
- 第二胶囊：真实样本阶段，零样本为 `阶段 0–500 条`。
- 第三胶囊：`前三命中 --`，并提供“前三命中率尚未形成”的可访问名称。

零样本状态不显示“样本不足”作为指标值，也不把“观察中”当作独立成熟度。

### 8.2 准备面板

评估未 ready 时隐藏全部三个现有任务模块，显示同一套准备面板：

零有效回测样本：

- 标题：`模型评估将在积累有效历史后开启`
- 说明：`评估按历史顺序回测，前 20 条用于建立上下文，不直接计入有效回测样本。`
- 进度：`0 / 20`
- 当前预测来源：`规则基线`
- 动作：`去工作台继续录入`

已有有效回测样本但未达到 20 条：

- 标题：`回测准备中`
- 进度：`evaluated_count / 20`
- 说明中同时区分总样本数和有效回测样本数。
- 动作：`去工作台继续录入`

只有 `evaluation.status === 'ready'` 时渲染核心回测、当前融合权重和子模型回测。

## 9. 共享组件与数据边界

### 9.1 纯展示状态模型

建立一个无副作用的共享模块，唯一负责：

- 规范化样本计数。
- 返回统一样本成熟度。
- 返回统一样本阶段范围。
- 返回评估准备度与 `evaluated_count / 20`。
- 格式化可选数值；真实 `0` 必须继续经过 formatter，只有 `null`、`undefined` 或非有限数返回 `--`。

统计页不再拥有独立成熟度映射，评估页不再拥有 `观察中 / 可参考 / 稳定` 的另一套函数。

### 9.2 共享准备面板

统计和评估共用 `SampleReadinessPanel`：

- 标题、说明、当前值、目标值、进度说明、来源说明和动作由 props 提供。
- 统计页通过 detail slot 放入现有阶段轴。
- 组件只提供一个主边界，不创建内部完整卡片。
- 主按钮使用现有 `.button-primary`。

### 9.3 请求新鲜度

保留当前初次加载流程，并增加按页面刷新的轻量入口：

- 进入统计页时刷新统计数据。
- 进入评估页时刷新评估数据。
- 录入一个档位时仍只做本地统计增量和后台预测刷新，不把统计与评估请求重新塞回高频保存路径。
- 切换账号或销毁工作台时，使旧请求失效，防止旧 UID 数据回写。

## 10. 视觉与排版

- 以模型评估当前页头胶囊的 32px 密度为基准。
- 零样本成熟度胶囊使用中性表面和边框；有样本状态沿用预测绿。
- `--` 使用 `--font-data`、`tabular-nums`、Label/Data SM 层级和次级文字色。
- 准备面板保持静态扁平，无阴影、无装饰渐变、无超大数字。
- 数值与单位拆分；`0 / 500`、`0 / 20` 使用稳定数字宽度。
- 不新增新的颜色 token；浅色和深色使用现有语义 token 等价映射。
- 860px 以下准备面板改为纵向排列；520px 下按钮占可用宽度，文字不低于 12px。

## 11. 可访问性

- 中性 `待录入` 不依赖颜色和状态点表达。
- 状态胶囊组保留 `role="group"` 和页面专属可访问名称。
- 进度使用原生 `<progress>` 或等价 `role="progressbar"`，提供 current、min、max。
- `--` 的可见字符保持简短，但每个位置必须有完整 `aria-label`。
- “去工作台录入”使用原生按钮；切换页面后工作台主区域仍按 DOM 顺序可达。
- 加载骨架标记 `aria-busy="true"`；错误信息使用 `role="alert"` 并提供“重新加载”。
- 所有新按钮保持至少 44px 点击高度和现有 `focus-visible` 轮廓。

## 12. 状态转换

```text
账号/UID 切换
  -> loading
  -> 请求成功且 total = 0
       -> 全局 0 / 0 / --
       -> 工作台首次录入提示
       -> 统计待录入准备面板
       -> 评估待录入准备面板
  -> 第一条样本保存成功
       -> total = 1
       -> 统一成熟度 = 起步观察
       -> 统计恢复真实分布任务卡
       -> 评估继续显示回测准备面板
  -> evaluated_count 达到 1..19
       -> 评估标题 = 回测准备中
  -> evaluation.status = ready
       -> 评估渲染完整任务模块和真实指标
```

## 13. 验收标准

- 同一样本数下，统计和评估页头的第一个状态胶囊文案完全一致。
- 零样本时两个页面都显示 `待录入`，且没有绿色状态点。
- 全局置信度明确显示 `--`，不显示“未建立”、`低` 或百分比。
- 真实计数全部显示 `0`，不会被通用 formatter 转成 `--`。
- 统计零样本不出现偏高、偏低、`0.00%`、`+0.00pp` 或 13 条空行。
- 评估未 ready 时不挂载三个完整任务模块，页头前三命中显示 `--`。
- 评估准备面板正确区分总样本与有效回测样本，并显示 `evaluated_count / 20`。
- 工作台零样本保持直接可录入，显示首次录入指引和规则基线来源。
- 空历史面板只在没有已保存偏好时默认最小化。
- 加载、错误、零样本和已有样本四种状态不会互相冒充。
- 浅色、深色、1440px、860px、520px 均无重叠、裁切或页面级横向溢出。
- 前端定向测试、全量测试、生产构建和 `git diff --check` 通过。
