# 首页完整字素打字机动画设计

## 背景与根因

首页标题“欢迎回家，漂泊者”当前通过 CSS 将标题容器从 `0` 扩展到 `8em`，并使用 `steps(8, end)` 模拟逐字显示。该实现假定每个字符的实际渲染宽度都严格等于 `1em`。字体度量、字重、缩放或浏览器取整一旦与该假设不一致，容器边界就会落入字形内部，动画过程中出现半个汉字。

浏览器采样确认，桌面端标题字号为 56px，动画按 56px 固定步进，而标题实际滚动宽度还包含字体和内边距的独立度量。问题来自连续宽度裁切，不是标题文本或 Vue 渲染数据错误。

完整字素实现上线后的冷缓存复现进一步发现第二层问题：标题文字“欢迎回家，漂泊者”分别命中 IBM Plex Sans SC Bold 的 `081`、`087`、`091`、`092`、`093`、`094` 六个 `unicode-range` 字体切片。旧宽度裁切实现从首帧就在 DOM 中保留完整标题，因此浏览器会提前准备全部切片；新实现从空字符串逐字追加，导致部分切片在对应字素出现时才开始加载。浏览器采样中标题 `opacity` 始终为 `1`，但“泊”字出现时 `document.fonts.status` 稳定经历 `loaded → loading → loaded`，确认用户感知到的文字闪烁来自字体切片加载和字形重绘，而不是光标动画或标题透明度变化。

## 目标

- 保留首页已批准的轻量终端打字机识别。
- 汉字、标点和其他 Unicode 字素只能完整出现，任何时刻都不能显示半个字形。
- 蓝色光标始终跟随当前可见文字末端。
- 字体切片在逐字动画开始前稳定，动画过程中不得再触发标题字体替换。
- 认证卡片在标题动画完成后出现，但登录、注册、输入、校验、保存账号和提交事件本身不依赖动画实现。
- 尊重减少动态效果偏好，并保持稳定的无障碍标题名称。

## 非目标

- 不修改标题文案、品牌标识、页面结构或认证业务逻辑。
- 不为其他页面新增通用动画框架。
- 不调整登录成功后的 UID 绑定和工作台流程。
- 不增加音效、循环打字、删除重打或其他装饰性动效。

## 推荐设计

### 动画前字体准备

桌面端准备播放标题动画时，先使用 `document.fonts.load()` 按标题实际的 `700 56px "IBM Plex Sans SC"` 字体描述和完整标题文本请求所有命中的字体切片。只有字体准备成功后才创建并启动逐字动画，保证每一帧直接使用最终字形，不在 fallback、不可见字形和正式字体之间切换。

字体准备最多占用 180ms。若浏览器不支持 Font Loading API、字体加载返回空结果、抛出错误或超过预算，则不继续播放逐字动画，而是直接显示完整标题并让认证卡片进入。该降级优先保证入口稳定和可交互，不让字体网络状态延长认证等待。

页面在字体准备期间进入后台、切换到减少动态效果、进入 520px 及以下窄屏或卸载组件时，应立即取消等待结果对界面状态的影响；后台、减少动态效果和窄屏仍直接得到完整标题与认证卡片。字体请求本身无法由浏览器 API 中止，但本地超时计时器必须清理，异步结果不得在组件卸载或静态降级后重新启动动画。

不采用以下替代方案：

- 不通过给整段标题增加淡入来掩盖字体替换，这会把一次字形重绘变成可见的明暗抖动。
- 不在页面中保留一份 `opacity: 0` 的重复完整标题来触发字体加载，避免重复 DOM、额外布局和无障碍维护成本。
- 不硬编码六个字体文件的构建产物路径，避免与 Vite 哈希、字体包版本和未来标题文案耦合。

### 完整字素渲染

标题不再通过 `width`、`max-width`、`overflow: hidden` 或 `clip-path` 裁切完整字符串。Vue 维护当前可见标题，每次只追加一个完整 Unicode 字素。

字素分割优先使用 `Intl.Segmenter`，不可用时使用 `Array.from` 作为兼容回退。当前中文标题在两种路径下均按完整字符推进；未来文案包含组合字符或 emoji 时，支持 `Intl.Segmenter` 的浏览器仍不会拆开可见字素。

标题结构包含独立的文字节点和光标节点。光标不再使用标题容器的 `border-right`，而是作为 `aria-hidden` 的行内元素跟随当前文字末端，因此不依赖估算字符宽度。

### 动画时序

- 页面挂载后等待约 150ms 开始。
- 普通字素间隔约 70ms。
- 中文逗号后增加约 120ms 的语义停顿。
- 总时长控制在约 0.8 秒，不延长当前入口等待感。
- 标题完成后只保留克制的光标闪烁，不循环重播文字。

动画只播放一次。认证卡片在标题完成后进入；登录与注册标签切换、字段输入、验证错误和表单提交都不会重新启动标题动画。

### 交互时序

认证卡片等待标题动画完成后再出现。等待期间卡片不能成为透明但仍可操作的控件：它必须退出键盘焦点顺序和指针命中区域，屏幕阅读器也不应提前进入尚未显示的认证表单。

标题完成后立即触发认证卡片进入，进入反馈控制在 160ms 内，只使用 `opacity` 和 `transform`，不再叠加额外的 1.1 秒延迟。卡片进入后，登录、注册、输入、校验和提交逻辑完全按现有流程工作，也不会因为标题或卡片动画重新播放而重置表单状态。

如果页面在动画过程中进入后台，标题立即完成并让认证卡片进入可用状态。用户返回页面时看到完整标题和认证入口，不补播积压帧。组件卸载时清理计时器和 `visibilitychange` 监听，避免页面切换后继续更新状态。

## 可访问性与响应式

- `h1` 始终提供完整且稳定的无障碍名称“欢迎回家，漂泊者”。
- 动态更新的可见文字与光标不触发屏幕阅读器逐字重复播报。
- `prefers-reduced-motion: reduce` 下立即显示完整标题，关闭逐字推进和光标闪烁。
- 520px 及以下继续直接显示完整标题，保持现有自然换行策略，不为窄屏强制播放动画。
- 标题容器继续保留稳定的最小高度，文字增长不得推动认证卡片或能力列表发生纵向跳动。

## 状态与失败处理

- 不支持 `Intl.Segmenter` 时自动回退，不显示错误，也不影响认证功能。
- 不支持 Font Loading API、字体准备失败、返回空结果或超过 180ms 时跳过逐字动画，直接显示完整标题和认证卡片。
- 计时器创建失败或组件提前卸载时，标题回到完整文本。
- 页面进入后台、启用减少动态效果或命中窄屏规则时，完整文本和已显示的认证卡片是唯一静态结果。

## 验证策略

- 添加失败测试，证明旧的宽度裁切、`steps(8)` 和标题 `overflow: hidden` 不再被接受。
- 为字素推进逻辑添加确定性测试，验证每一帧都是完整标题的合法字素前缀，并包含标点停顿与最终完整状态。
- 为字体准备控制器添加确定性测试，验证完整标题与正确字体描述传入 `FontFaceSet.load()`，并覆盖成功、空结果、异常、超时和取消。
- 添加组合函数契约测试，确认字体准备成功前不会启动逐字控制器；失败或超时时直接完成标题和认证卡片。
- 添加时序测试，确认认证卡片在标题完成前不可聚焦、不可点击且不进入无障碍树，标题完成后立即可用。
- 保留并运行现有认证组件测试，确认卡片出现后的登录、注册、校验、账号保存和提交事件未改变。
- 运行完整前端测试和生产构建。
- 在桌面端浏览器采样动画中间状态，确认没有半字、光标跟随文字末端，认证卡片只在标题完成后出现并可聚焦。
- 在窄屏和减少动态效果条件下确认标题与认证卡片立即完整显示、页面无横向溢出。

## 验收标准

- 动画任意帧都只包含完整字素，不再出现半个汉字。
- 冷缓存逐帧采样中，标题动画开始后 `document.fonts.status` 不再因标题字素出现而进入 `loading`，已有文字不发生字体替换闪烁。
- 光标在打字过程中紧随当前文字，结束后停在完整标题末端。
- 标题动画约 0.8 秒完成，只播放一次。
- 认证卡片在标题完成前不可交互，标题完成后立即出现并可切换认证模式、输入和提交。
- 后台页面、减少动态效果和窄屏均直接得到完整标题与认证卡片。
- 字体准备失败或超过 180ms 时跳过动画，认证入口不因字体网络状态长期阻塞。
- 认证数据流与后续 UID 绑定流程保持不变。
