# 《鸣潮》声骸副词条预测与玄学规律探测工具设计

## 目标

开发一个可部署的 Web 应用，用于持续记录《鸣潮》声骸副词条数据，并研究实际观测结果是否偏离规则基线。工具不能宣称确定性预测结果，只输出概率排名、模型依据、置信度、样本量和数据不足提示。

第一版采用保守的“科学基线 + 玄学探测”集成贝叶斯方案：

```text
P_final = w0 * P_rule + w1 * P_bayes + w2 * P_markov + w3 * P_context
```

初始权重：

```text
w0 = 0.70
w1 = 0.25
w2 = 0.05
w3 = 0.00
```

上下文变量和顺序依赖从第一版开始记录，但只有在样本量、效应量、稳定性和验证集指标都支持时，才允许影响预测。

## 当前项目上下文

当前仓库已有：

- `Wuwa`：Django 后端，目前包含健康检查接口。
- `WuwaFrontend`：Vue 3 + Vite 前端，目前包含后端连通性检查。
- SQLite 开发数据库。

实现时应扩展现有结构，不重建项目。

## 产品范围

第一版包含：

- 轻量账号系统。
- 用户数据隔离。
- 声骸与副词条逐条手动录入。
- 后端硬编码手册规则和档位概率表。
- 规则基线预测。
- Dirichlet 贝叶斯总体预测。
- 马尔科夫模型和上下文模型接口，并带保守样本量门槛。
- 统计看板。
- 模型评估页。

第一版不包含：

- CSV 导入导出。
- OCR 或截图识别。
- 公共共享数据池。
- 社交、排行榜或公开排名功能。
- 在证据不足时给出强上下文规律或顺序规律结论。

## 架构

后端：

- 使用 Django。
- 使用 Django 内置用户系统实现轻量账号。
- 本地开发继续使用 SQLite。
- 数据模型按后续可迁移到 PostgreSQL 的方式设计。
- 新增规则、贝叶斯更新、融合预测、上下文检验、模型评估等服务层。
- 向 Vue 前端提供 JSON API。

前端：

- 使用 Vue 3 + Vite。
- 登录/注册流程。
- 声骸录入和预测工作台。
- 统计看板。
- 模型评估页面。

数据流：

1. 用户注册或登录。
2. 用户创建或选择一个声骸记录。
3. 用户逐条录入副词条。
4. 后端校验并保存记录。
5. 后端重新计算该用户的预测和统计。
6. 前端展示更新后的概率排名、依据和警告。

## 规则来源

规则基线来自 `鸣潮常识手册.pdf` 第 9 部分。

第 9.2 的关键原则：

- 孔位对词条无影响。
- 各词条出率均等。
- 不同档位出率不同。

第一版默认游戏实现采用：

- 从合法剩余副词条池中均匀抽取词条。
- 抽到词条后，按该词条对应的固定档位权重抽取数值。
- 同一声骸内不重复出现同名副词条。

手册未明确写出“同一声骸内不重复同名副词条”，但该工具将其作为领域约束纳入规则基线。

## 副词条池

合法副词条池包含 13 个独立副词条：

- `crit_rate`：暴击率
- `crit_damage`：暴击伤害
- `basic_attack_damage`：普攻伤害加成
- `skill_damage`：共鸣技能伤害加成
- `heavy_attack_damage`：重击伤害加成
- `liberation_damage`：共鸣解放伤害加成
- `atk_percent`：攻击百分比
- `hp_percent`：生命百分比
- `def_percent`：防御百分比
- `flat_atk`：攻击固定值
- `flat_hp`：生命固定值
- `energy_regen`：共鸣效率
- `flat_def`：防御固定值

手册中的 `AEZR/大攻击/大生命` 一栏不是一个合并词条，而是 6 个独立词条共享同一套档位概率：

- 普攻伤害加成
- 共鸣技能伤害加成
- 重击伤害加成
- 共鸣解放伤害加成
- 攻击百分比
- 生命百分比

## 数据模型

### EchoRecord 声骸记录

字段：

- `user`：所属用户。
- `echo_uid`：用户自定义声骸 ID。
- `display_name`：用户给声骸起的简短名称，可为空。
- `cost`：1、3 或 4。
- `set_name`：套装。
- `main_stat`：主词条。
- `source`：获取来源、副本、合成方式或备注。
- `tuning_batch_id`：同一批连续调谐标识，可为空。
- `is_continuous_tuning`：是否连续调谐。
- `status`：记录状态，例如 `in_progress`、`completed`、`archived`。
- `last_tuned_at`：最近一次录入副词条时间，用于排序和快速回到正在强化的声骸。
- `created_at`：创建时间。
- `updated_at`：更新时间。

校验：

- 用户只能访问自己的声骸记录。
- `cost` 必须是 1、3 或 4。
- `main_stat` 应按 COST 校验合法主词条。

### SubstatRoll 副词条记录

字段：

- `echo`：所属声骸。
- `position`：第几个副词条，范围 1 到 5。
- `substat_type`：13 个合法副词条之一。
- `tier_value`：实际档位数值。
- `tuned_at`：调谐时间。
- `enhance_phase`：强化等级段，例如 `+5`、`+10`、`+15`、`+20`、`+25`。
- `tuning_order`：同批调谐顺序，可为空。
- `created_at`：创建时间。

校验：

- 同一声骸不能重复出现同名 `substat_type`。
- 同一声骸不能重复出现同一个 `position`。
- `tier_value` 必须属于该 `substat_type` 的合法档位。
- 用户不能给其他用户的声骸创建副词条记录。

## 预测模型

### P_rule 规则基线

规则基线流程：

1. 从 13 个副词条开始。
2. 排除当前声骸已经出现的副词条。
3. 对剩余合法候选赋予均匀概率。
4. 对每个候选词条使用其固定档位概率表。

该模型不使用孔位、套装、来源、时间、前一个副词条或其他上下文变量。

### P_bayes 总体贝叶斯模型

Dirichlet 总体模型：

- 统计该用户历史记录中 13 个副词条的出现次数。
- 使用 Dirichlet 平滑，避免小样本下概率变成 0 或 1。
- 输出 13 个副词条的后验概率。
- 对当前声骸排除已出现副词条后重新归一化。

该模型用于检测用户整体观测分布是否偏离均匀规则基线。

### P_markov 马尔科夫顺序探测模型

顺序依赖探测：

- 记录“上一个副词条 -> 下一个副词条”的转移频率。
- 使用加性平滑。
- 当转移样本量低于门槛时回退到 `P_rule`。
- 在早期样本阶段不允许成为强预测模型。

### P_context 上下文玄学模型

记录和检验的上下文变量：

- COST。
- 套装。
- 主词条。
- 第几个副词条。
- 调谐顺序。
- 强化等级段。
- 获取来源。
- 时间段。
- 是否连续调谐。

默认假设：

- 上下文变量不影响概率，除非数据给出足够证据。

每个上下文因素都有证据状态：

- `insufficient_data`：样本不足。
- `monitoring`：监控中。
- `supported`：当前数据支持该因素影响概率。
- `contradicted`：当前数据反驳该因素影响概率。
- `inconclusive`：证据不明确。

套装影响的处理：

- 零假设 `H0`：套装不影响副词条概率。
- 备择假设 `H1`：套装影响副词条概率。
- 后台持续按套装分组统计，并与规则基线和用户总体基线比较。
- 只有当样本量、效应量、稳定性和验证集改善都达到门槛时，套装影响才变成 `supported`。
- 如果后续数据不再支持，已支持的上下文因素可以降级回 `inconclusive`。

### 融合模型

初始融合公式：

```text
P_final = 0.70 * P_rule + 0.25 * P_bayes + 0.05 * P_markov + 0.00 * P_context
```

未来可以用验证集指标动态调整权重：

- Log loss。
- Brier score。
- Top-1 命中率。
- Top-3 命中率。

验证集应按时间切分，避免用未来数据解释过去预测。

## 样本阶段

应用应展示用户当前所处样本阶段：

- 0 到 500 条：主要相信规则基线，以记录数据为主。
- 500 到 3000 条：启用总体贝叶斯偏离检测。
- 3000 到 10000 条：评估 COST、主词条、套装、第几个词条等上下文变量。
- 10000 到 50000 条：评估马尔科夫顺序依赖。
- 50000 条以上：优化上下文模型和融合权重。

这些是指导性门槛。具体启用仍需结合单个因素的样本量和验证集证据。

## 预测输出

预测 API 应返回：

- 候选副词条概率排名。
- 每个候选的 `P_final`。
- 每个候选的 `P_rule`。
- 相对规则基线偏离。
- 候选词条的档位概率表。
- 当前模型权重。
- 当前样本阶段。
- 置信度标签。
- 判断依据。
- 样本不足警告。

界面禁止使用“必出”“锁定”“保底”“确定会出”等确定性表达。

## 页面设计

### 登录与注册页

- 用户名和密码注册。
- 用户名和密码登录。
- 第一版不做邮箱、找回密码、第三方登录。

### 工作台

工作台应尽量直观，避免让用户通过传统表单控件反复选择。核心录入方式是“点击式副词条与档位矩阵”：把 13 个副词条和每个词条对应的全部合法档位、档位概率直接展示出来，用户按实际强化结果依次点击。

工作台包含四个功能区：

- 当前声骸摘要：声骸 ID、名称、COST、套装、主词条、来源、已出现副词条、当前强化进度。
- 历史声骸列表：显示最近强化过的声骸、未完成声骸、已完成声骸，支持一键切换回任意声骸继续录入。
- 点击式副词条矩阵：展示 13 个副词条，每个副词条下直接展开合法档位和对应概率。
- 预测面板：剩余合法候选排名、规则基线概率、偏离幅度、置信度和解释。

交互：

- 用户点击某个“副词条 + 档位”格子，即记录一次副词条结果。
- 已出现的同名副词条在矩阵中置灰、不可再次点击，并显示“已出现”状态。
- 不合法档位不会显示为可点击项。
- 系统自动推断下一个 `position`，用户也可以在需要修正时切换第几个副词条。
- 每次点击录入前显示轻确认或撤销入口，避免误点污染数据。
- 保存副词条后刷新预测和统计。
- 用户可以先录入声骸 A 的 3 个副词条，切换到声骸 B 录入，再回到声骸 A 继续录入剩余词条。
- 历史声骸列表按 `last_tuned_at` 和状态排序，优先显示正在强化且未满 5 个副词条的声骸。
- 每个声骸卡片展示已有副词条序列和档位，方便用户判断是否回到正确声骸。

### 统计看板

展示：

- 总样本量。
- 当前样本阶段。
- 13 个副词条实际频率 vs 均匀规则基线。
- 档位分布 vs 手册档位概率表。
- 套装、COST、主词条、第几个词条、来源、时间段、连续调谐等上下文因素状态。
- 带样本量和效应量的证据摘要。

### 模型评估页

展示：

- 当前融合权重。
- Log loss。
- Brier score。
- Top-1 和 Top-3 命中率。
- `P_rule`、`P_bayes`、`P_markov`、`P_context`、`P_final` 横向比较。
- 当某个模型只监控、不参与融合时，应明确说明。

## 防误判规则

每个玄学结论都必须展示：

- 样本量。
- 证据状态。
- 效应量或偏离程度。
- 置信度。
- 是否参与预测。
- 是否改善验证集指标。

系统必须支持结论降级：当后续数据不再支持时，之前的 `supported` 可以回到 `inconclusive`。

界面必须把所有结论表述为概率性、证据驱动的判断，不能包装成确定性预测。
