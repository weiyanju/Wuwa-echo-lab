# 模型评估详情收起视口锚定设计

## 背景

“子模型回测”使用原生按钮控制单项详情的条件渲染。当前实现移除了详情面板的离场高度动画，收起时由 Vue 立即把详情节点移出文档流。

这种处理解决了固定 `max-height` 动画造成的停顿和错误折叠方向，但没有覆盖用户滚动后的浏览器行为。评估页以 `HTML` 作为滚动根节点，并使用浏览器默认的 `overflow-anchor: auto`。当用户滚动到展开详情的中下部后，浏览器可能选中详情下方的模型行作为滚动锚点。详情被立即移除时，浏览器会自动修改页面滚动位置以维持该锚点，导致被点击的模型标题行在屏幕中向下移动，形成“向下回收”的视觉结果。

这不是第二套 CSS 动画，也不是应用代码调用了 `scrollIntoView`。根因是条件渲染造成的大块文档流变化与浏览器滚动锚定之间缺少显式协调。

## 目标

收起详情或切换到另一子模型详情时，被用户点击的模型标题行保持在点击前的屏幕纵向位置。详情移除后，后续内容向上补位，不出现页面跳动、向下回收或二次平滑滚动。

## 非目标

- 不恢复 `max-height`、`height`、`margin` 或 `padding` 离场动画。
- 不改变现有单项展开状态、箭头方向、ARIA 文案或键盘操作。
- 不全局关闭浏览器滚动锚定。
- 不修改子模型数据、排序、权重或回测算法。
- 不增加新的视觉样式或动画。

## 方案比较

### 方案 A：显式保持点击标题行的视口位置

状态变化前记录被点击标题行的 `getBoundingClientRect().top`，Vue 完成 DOM 更新后再次测量同一元素，并把两次位置差加到实际滚动容器的 `scrollTop`。

优点：

- 直接表达产品要求，不依赖浏览器如何选择滚动锚点。
- 仅影响本次详情切换，不改变页面其他模块。
- 同时适用于关闭当前项和切换到另一项。
- 不需要恢复布局属性动画。

代价：

- 每次详情切换进行两次元素位置读取和一次有条件的滚动修正。
- 需要处理元素失效、滚动容器缺失和亚像素误差。

### 方案 B：关闭滚动锚定

通过 `overflow-anchor: none` 禁用页面或模块的浏览器滚动锚定。

不采用。模块级禁用不能保证浏览器不会选择模块外的后续内容作为锚点；根节点级禁用会影响图片加载、数据刷新及其他可折叠区域，作用范围过大。

### 方案 C：恢复离场高度动画

通过测量高度或固定 `max-height` 让详情逐步退出文档流。

不采用。逐帧布局变化仍可能触发滚动锚定，而且会重新引入布局重排、内容高度上限和动画时长不准确等问题。

## 选定设计

采用方案 A。

### 交互流程

1. 用户点击某个子模型标题行。
2. 立即保存该按钮元素及其相对视口的纵向位置。
3. 更新 `selectedModelDetailKey`：
   - 点击当前展开项时设为 `null`；
   - 点击其他项时设为新模型键。
4. 等待 Vue 完成本轮 DOM 更新。
5. 确认原按钮仍连接在当前文档中。
6. 重新读取按钮相对视口的位置。
7. 计算 `afterTop - beforeTop`。
8. 当绝对差值达到 `1px` 时，把该差值加入滚动根节点的 `scrollTop`。
9. 不使用 `behavior: smooth`，避免用户看到补偿过程。

位置补偿公式：

```text
newScrollTop = currentScrollTop + (afterTop - beforeTop)
```

如果浏览器已经自动保持按钮位置，两次位置差为零，应用不做任何滚动操作。如果浏览器把按钮向下移动，补偿会把页面向下滚动相同距离，使按钮回到原屏幕位置。

### 代码边界

视口保持逻辑应作为独立小函数存在，负责：

- 接收锚点元素和一次同步状态修改操作；
- 读取滚动根节点；
- 在 Vue 更新后完成位置补偿；
- 对非浏览器环境、失效元素和微小差值安全退出。

`EvaluationBacktest.vue` 只负责把 `event.currentTarget`、模型键和状态修改传给该函数，不在模板或 CSS 中实现滚动策略。

当前页面滚动根节点是 `document.scrollingElement`。实现不假设它一定是 `HTML`，以便未来页面改为独立滚动容器时能够集中调整。

### 并发和边界条件

- 连续快速点击时，仅允许最后一次仍有效的状态修改执行补偿，避免旧测量覆盖新交互。
- 元素在更新后不再连接到文档时不补偿。
- `document.scrollingElement` 不存在时不补偿。
- 差值小于 `1px` 时不补偿，避免亚像素抖动。
- 直接修改 `scrollTop`，不受全局 `scroll-behavior` 影响。
- 接近文档顶部或底部时允许浏览器对 `scrollTop` 进行自然钳制。
- `prefers-reduced-motion` 不改变位置稳定要求；该修正不是装饰动画。
- 保留点击按钮的焦点，不主动调用 `focus()`。

## 状态和可访问性

现有 disclosure 语义保持不变：

- 触发元素继续使用原生 `button`。
- `aria-expanded` 与实际详情状态同步。
- 动态 `aria-label` 保持“展开/收起模型详情”语义。
- 箭头只表达展开状态，不承担视口补偿职责。
- 键盘触发与鼠标触发使用相同的锚点保持逻辑。

## 测试设计

### 单元测试

- 收起当前项时，状态从模型键变为 `null`。
- 切换模型时，状态变为新模型键。
- `afterTop - beforeTop` 为正、负和零时计算正确。
- 差值小于 `1px` 时不修改滚动位置。
- 元素断开连接或滚动根节点缺失时安全退出。
- 快速连续操作时旧操作不执行最终补偿。

### 组件结构测试

- 点击处理函数接收事件中的当前按钮元素。
- 继续保留现有 `Transition`、`v-if`、ARIA 和箭头状态。
- CSS 不重新引入详情离场高度动画或固定 `max-height`。

### 浏览器验证

在真实评估数据和以下场景下记录点击前后标题行的 `getBoundingClientRect().top`，误差应小于 `1px`：

1. 展开后立即收起。
2. 展开后向下滚动，再收起。
3. 展开一个模型后向下滚动，再点击另一个模型。
4. 页面接近顶部、页面中段和接近底部。
5. 浅色模式和深色模式。
6. 桌面宽屏、窄屏和移动端断点。
7. 鼠标点击、键盘 Enter 和 Space。
8. `prefers-reduced-motion: reduce`。

## 性能

每次详情切换最多执行两次几何读取和一次有条件的 `scrollTop` 写入，不创建持续监听器、`ResizeObserver` 或逐帧动画。该成本只发生在用户主动操作时，且限定在一个标题行元素上。

## 验收标准

- 用户滚动前后收起详情，所点击标题行均保持在原屏幕位置。
- 后续模型行只向上补位，不出现向下跳动。
- 切换模型详情时不会发生双向页面跳动。
- 不出现平滑滚动、闪烁或延迟离场。
- 不改变展开动画、箭头、焦点和 ARIA 行为。
- 不全局修改滚动锚定设置。
- 自动化测试、前端完整测试、生产构建和 `git diff --check` 通过。
