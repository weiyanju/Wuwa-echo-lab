# 登录框内 UID 首次绑定设计

**日期：** 2026-07-19  
**状态：** 已批准设计方向，待实施计划  
**适用范围：** `WuwaFrontend` 登录入口中的首次 UID 绑定流程

## 1. 决策摘要

用户完成登录或注册后，如果当前系统账号没有可用 UID，不再离开登录页进入独立的 UID 初始化页面。右侧登录框在保持外层页面和自身外框稳定的前提下，从认证内容切换为 UID 绑定内容。

这是登录框内部的任务页面切换，不是整页导航、步骤条或卡片推进。

后续新增、切换 UID 继续归属登录后的顶部账号菜单。本设计只处理首次绑定。

## 2. 设计目标

- 缩短“认证 → 首次绑定 UID → 进入工作台”的路径。
- 让首次绑定延续用户刚刚使用的登录入口，不制造第二个页面语境。
- 保持账号、`GameAccount` 和 UID 的既有业务模型。
- 明确限制实施边界，避免顺带改造已经获得认可的登录页面。
- 保持登录入口与工作台总体统一，同时允许登录页保留独立的浅色终端语言。

## 3. 冻结范围

以下内容不因本设计发生视觉、文案或布局调整：

- 顶部 `TETHYS` 品牌与 `SYSTEM.ONLINE` 状态。
- 登录页背景、点阵、页面留白与两栏布局。
- 左侧协议标签、主标题、标题动画和能力列表。
- 登录 / 注册页现有字段、标签、按钮文案和切换方式。
- 登录框在页面中的位置、宽度、边框、底色和总体视觉语言。
- 登录后的工作台、顶部导航、UID 切换菜单和主题切换。
- 后端认证、`GameAccount`、UID 校验、绑定和数据归属规则。

如实施发现冻结内容必须变化，必须停止并重新确认，不能把变化作为本设计的隐含组成部分。

## 4. 允许改动范围

只允许调整右侧登录框内部的状态和首次 UID 绑定内容：

- 登录框新增“认证页”和“UID 绑定页”两个内部页面状态。
- 认证成功后根据既有 `workspaceLocked` / UID 状态决定内部页面或工作台去向。
- UID 绑定页的返回图标、标题、说明、输入、错误、提交和忙碌状态。
- 两个内部页面之间的方向性过渡。
- 为实现以上流程所需的最小 props、events、状态编排和测试。
- 将独立 UID 初始化视图退出当前 Web 首次绑定渲染路径；是否删除旧文件由实施计划根据引用和测试情况确定。

## 5. 状态与导航

### 5.1 进入路径

```text
未认证
  → 登录框：认证页
  → 登录或注册成功
      → 已有可用 UID：进入工作台
      → 没有可用 UID：登录框切换到 UID 绑定页
```

进入 UID 绑定页时：

- 外层登录页保持原位，不重新播放标题动画。
- 登录框外框不退出、不重新进入，也不发生卡片推进。
- UID 输入获得焦点；减少动态效果时也必须完成该焦点转移。

### 5.2 返回路径

UID 绑定页左上角提供返回图标。该操作的业务含义不是普通的“上一步”，而是：

1. 退出当前系统账号。
2. 清空当前账号与 UID 临时状态。
3. 登录框反向切回认证页。

控件必须具有可访问名称 `退出当前账号并返回登录`，可通过 `aria-label` 和同义 `title` 提供。视觉上使用左箭头，但不能只依赖图形表达退出含义。

### 5.3 提交路径

- 无效 UID：停留在 UID 绑定页，在输入区域附近显示既有校验错误。
- 请求中：禁用返回、输入和提交，避免绑定与退出竞态。
- 绑定成功：进入工作台。
- 绑定失败：停留在 UID 绑定页，保留已输入 UID 并显示错误。

## 6. 登录框内部结构

### 6.1 认证页

认证页保持现有登录 / 注册结构和文案，不因新增内部导航而重排。

### 6.2 UID 绑定页

建议结构：

```text
┌────────────────────────────────────┐
│ [←] 绑定游戏 UID                   │
│      首次进入需要绑定一个游戏账号。 │
│                                    │
│      > 游戏 UID                    │
│      [ 输入你的 UID              ] │
│      可在游戏个人信息页查看 UID     │
│                                    │
│      [       BIND_AND_ENTER()     ] │
└────────────────────────────────────┘
```

规则：

- 返回图标位于登录框内部、标题左侧，属于当前任务页头。
- 图标按钮点击区域至少 `44 × 44px`。
- 标题、说明、字段和主按钮沿用登录框已有排版、边框和蓝色主动作语言。
- UID 数字使用项目 Data 字体角色和 `tabular-nums`。
- 不显示 `2 / 2`、进度条、步骤圆点或“下一步”语义。
- 不展示工作台导航、UID 胶囊、主题切换或账号菜单。
- 不新增装饰性插画、轨道图形、仪表盘或独立 onboarding 卡片。

## 7. 外框稳定性

登录框是固定的任务窗口。内部页面切换必须遵循：

- 外框宽度不变。
- 外框边框、底色和阴影不变。
- 桌面端采用稳定的最小高度，避免登录页与 UID 页切换时外框明显跳变。
- 注册页内容较高时允许内部高度按既有行为自然适配，但不能为 UID 页面单独创建第二套尺寸。
- 窄屏继续沿用当前登录页响应式规则，不重新设计外层布局。

## 8. 动效

认证页到 UID 页：

- 认证内容向左轻移并淡出。
- UID 内容从右侧轻移并淡入。

返回登录：

- 使用相反方向。

约束：

- 只动画 `opacity` 和 `transform`。
- 建议位移 `12–20px`，时长 `160–220ms`，使用克制的 ease-out。
- 不动画外框尺寸、边框、背景或页面两栏。
- `prefers-reduced-motion: reduce` 时取消位移并缩短或取消淡入淡出。
- 页面切换期间隐藏的内部页面不能进入焦点顺序或无障碍树。

## 9. 组件与数据职责

推荐职责边界：

- 登录入口组件负责外层登录页、登录框内部页面状态和两个内部页面的呈现。
- 认证表单继续只发出认证命令，不直接调用 API。
- UID 绑定表单继续负责输入规范化与局部校验，并发出绑定命令。
- `App.vue` 或既有上层编排继续调用 `useAuth`、`useGameAccount`，决定认证、绑定、刷新和退出顺序。
- `useGameAccount` 和后端继续拥有 `GameAccount` / UID 业务规则。

实施时优先把登录框的内部页面拆成清晰的小组件，不能为了合并页面而加厚 `App.vue`，也不能把 API 调用写进纯视图。

## 10. 登录页设计语言

登录页是 Tethys 工作台的入口场景，可以保留独立但同源的浅色终端语言：

- 协议标签、状态短语和命令式主按钮建立入口仪式感。
- 更硬朗的边角和 1px 边框属于当前登录页已经批准的特征。
- 与工作台的一致性来自字体角色、Tethys 蓝、信息层级、线性图标、克制动效和低噪音表面，而不是要求所有圆角完全一致。

实施时应更新既有 `docs/web-homepage-terminal-design.md` 中与当前登录页相冲突的圆角描述，并在根级 `DESIGN.md` 中加入最小范围的入口场景引用。不要另建一份重复的登录页视觉规范。

## 11. Hallmark 样式指纹

统一样式入口 `WuwaFrontend/src/style.css` 顶部需要增加一段短声明，记录现有系统，而不是定义新系统：

```css
/*
 * Hallmark
 * Genre: modern minimal data workbench
 * Tone: restrained terminal entry, calm analytical workspace
 * Palette anchor: Tethys blue
 * Structural fingerprint: split terminal entry → task-focused workbench
 */
```

声明必须位于现有 `@import` 之前；现有 import 顺序和 token 文件保持不变。除本设计明确需要的登录框内部状态样式外，不新增平行 token 体系。

## 12. 验收标准

- 未认证时，登录页与当前页面在外层结构、文案和视觉上保持一致。
- 登录 / 注册成功且已有 UID 时，仍直接进入工作台。
- 登录 / 注册成功且没有 UID 时，只有登录框内部切换到 UID 绑定页。
- 切换过程中外层标题、能力列表、背景和登录框外框不重新进入或移动。
- UID 页的返回图标位于框内标题左侧。
- 返回图标触发退出并回到认证页；不能保留已认证但无 UID 的后台会话。
- UID 输入继续执行九位数字规范化和既有校验。
- 请求中不能重复提交或同时返回。
- 绑定成功进入工作台；失败停留并给出可访问错误。
- 动效支持 `prefers-reduced-motion`。
- 后续新增 / 切换 UID 的顶部账号菜单不变。
- `App.vue` 不因本功能承担新的表单细节或 API 规则。
- `DESIGN.md`、登录页专项规范和 `style.css` 指纹与最终实现一致。

## 13. 非目标

- 重设计完整登录页。
- 修改登录 / 注册字段、文案或认证规则。
- 修改工作台 UI 或顶部账号菜单。
- 修改 UID 数量上限、不可变规则或后端数据模型。
- 把首次绑定做成多步骤 onboarding。
- 为登录页建立第二套全局设计系统。
