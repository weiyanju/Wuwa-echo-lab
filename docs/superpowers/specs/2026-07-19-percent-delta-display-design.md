# 百分比差值展示设计

**状态：** Approved

**日期：** 2026-07-19

**适用范围：** `WuwaFrontend` 统计诊断、模型评估、共享格式化函数、相关测试与当前有效设计规范

**关联规范：** `DESIGN.md`、`docs/product-interface-principles.md`、`docs/web-ui-design-system-v2.md`

## 1. 背景与决策

统计诊断中的观察率偏差，以及模型评估中的新增覆盖，本质上都是两个比例的绝对差。现有界面使用百分点缩写表达，数学语义准确，但普通玩家需要额外理解单位，降低了扫读效率。

本次决定将所有面向用户的比例差统一显示为带正负号的百分号数值，例如：

- 统计偏差显示 `+18.18%` 或 `-6.64%`。
- Top3 相对 Top1 的新增覆盖显示 `+1.45%`。
- Top5 相对 Top3 的新增覆盖显示 `+5.80%`。

底层计算不变：比例原始值继续使用 `0..1` 小数，两个比例先相减，再乘以 `100` 形成展示数值。本次只改变展示单位、命名和说明，不把绝对差改成相对增长率。

## 2. 设计目标

1. 让玩家无需理解专业缩写即可直接读懂比例差。
2. 统计页、评估页和共享格式化函数使用同一套展示规则。
3. 通过“偏差”“相对某项新增”等上下文降低百分号的语义歧义。
4. 保持数据计算、排序、图表比例、颜色语义和 API 契约不变。
5. 更新当前有效规范，同时保留历史计划和归档记录的原始事实。

## 3. 非目标

- 不修改后端统计或评估算法。
- 不修改 API 字段、数据库或 `GameAccount` 数据边界。
- 不把绝对差改为相对变化率。
- 不重新设计统计卡片、评估图表、颜色、间距或响应式布局。
- 不批量改写 `docs/archive/` 和已经完成的 `docs/superpowers/plans/`。

## 4. 展示规则

### 4.1 普通比例

观察率、理论率、累计命中率和图表刻度继续使用现有 `formatPercent`，例如 `31.18%`、`13.00%` 和 `20%`。

### 4.2 比例差

比例差使用独立的 `formatSignedPercentDelta`：

- 输入 `0.1818`，输出 `+18.18%`。
- 输入 `-0.0664`，输出 `-6.64%`。
- 输入 `0`，输出 `+0.00%`。
- 非有限值保持现有共享格式化行为，以 `0` 作为格式化兜底；业务层尚未形成的指标仍显示 `--`，不调用该格式化函数。

独立函数仍有必要，因为比例差需要正号，而普通比例不需要。函数名使用 `Delta` 明确它是差值，避免把它误解成普通比例或相对增长率。

### 4.3 上下文消歧

界面不新增工具提示或解释卡片，依靠现有任务语境表达含义：

- 统计页继续使用“副词条分布偏差”“当前偏高”“当前偏低”和“基线”等标签。
- 统计行同时展示观察率，标题说明继续给出观察值与基线关系。
- 评估页继续使用“相对首选新增”“相对前三新增”的可访问说明。

可访问名称使用完整比较关系，例如“相对首选新增 1.45%”。不得使用“增长率”“提升率”或其他会暗示相对变化率的文案。

### 4.4 空状态

尚未形成的指标继续显示半角 `--`，不附带 `%` 或其他单位。零样本时不渲染 `0.00%` 或 `+0.00%` 假指标，继续使用现有行动导向的准备状态。

## 5. 组件与代码边界

### 5.1 共享格式化

`WuwaFrontend/src/services/formatters.js` 拥有比例展示规则：

- 保留 `formatPercent` 和 `formatSignedPercent`。
- 将 `formatSignedPercentagePoints` 替换为 `formatSignedPercentDelta`。
- 不保留旧函数别名，避免新代码继续传播旧单位语义。

### 5.2 统计诊断

`WuwaFrontend/src/features/statistics/StatisticsView.vue` 继续拥有统计页组合：

- 偏高摘要、偏低摘要、逐行偏差值和标题说明统一调用 `formatSignedPercentDelta`。
- 排序、偏差方向、绝对值比例和图表宽度计算不变。

### 5.3 模型评估

`WuwaFrontend/src/features/evaluation/EvaluationCoreBacktest.vue` 继续拥有核心回测展示：

- Top3、Top5 的相邻累计命中率差值统一调用 `formatSignedPercentDelta`。
- 可访问名称改为百分号展示，但继续明确比较对象。
- 累计命中率、横轴和柱长计算不变。

## 6. 数据流

```text
后端返回 0..1 比例
  -> 页面计算两个比例的绝对差
  -> formatSignedPercentDelta
  -> 乘以 100、保留指定小数位、添加正负号和 %
  -> 统计偏差或评估新增覆盖
```

本次数据流没有新增状态、缓存、请求或持久化步骤。

## 7. 文档策略

当前有效规则按新决策更新：

- `DESIGN.md` 中统计诊断的比例差规则改为百分号展示。
- `DESIGN.md` 中空指标和零样本示例同步移除旧单位。

历史资料保持原文：

- `docs/archive/` 记录当时实际采用过的设计，不改写。
- 已完成的 `docs/superpowers/plans/` 和旧设计记录作为历史背景保留。
- 本次实现完成后新增归档记录，说明现行展示已经切换为百分号。

因此，全仓库搜索仍可能在历史资料中看到旧单位；这不代表当前产品仍采用旧规则。

## 8. 错误与边界处理

- `null`、`undefined` 或非有限评估差值继续由组件显示 `--`。
- 统计数据若进入共享格式化函数，沿用现有非有限值兜底，不在本次扩大行为变更。
- 正负号规则保持不变，零值仍显示正号，以维持偏差列表的稳定格式。
- 小数位默认保持两位；图表刻度和普通百分比继续使用各自现有精度。
- 改动不得改变读屏顺序、图表角色或键盘交互。

## 9. 测试与验收

### 9.1 自动化测试

- 格式化测试锁定 `+18.18%`、`-6.64%` 和 `+0.00%`。
- 统计组件测试锁定新格式化函数的使用，并确认旧函数名不再出现。
- 评估核心回测测试锁定新格式化函数和百分号差值语义。
- 现有前端测试全部通过。
- 前端生产构建通过。

### 9.2 静态检查

- 产品源码中不再出现旧单位缩写、旧格式化函数名或“个百分点”用户文案。
- 当前有效规范与实现一致。
- 历史计划和归档中的旧记录不计入失败。
- `git diff --check` 通过。

### 9.3 视觉验收

- 统计页偏高、偏低摘要及每行偏差均显示 `%`。
- 评估页 Top3、Top5 新增覆盖均显示 `%`。
- 数值宽度、对齐、颜色、换行和图表布局无视觉漂移。
- 零样本和未形成指标不出现带单位的零值。
- 浅色、暗色与窄屏布局保持现状。

## 10. 已否决方案

### 保留专业单位并增加解释

数学表达最严格，但仍要求玩家学习额外单位，没有解决本次可读性目标。

### 改写全部历史资料

可以让全仓库搜索结果完全一致，但会把过去的设计与实施记录改写成从未发生过的新事实，不符合仓库的归档原则。

### 将差值改为相对增长率

这会改变数据含义。例如从 `13%` 到 `18%` 的绝对差与相对增长率数值不同，属于算法和产品指标变更，不在本次范围内。
