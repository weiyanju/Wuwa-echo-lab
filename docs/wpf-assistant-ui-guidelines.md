# WPF 本地助手 UI 规范

## 1. 文档定位

本文定义 `Wuwa` WPF 本地助手的长期 UI 规范。

它只约束 WPF 登录窗口、本地助手主窗口、左侧导航、首页、识别页、截图/OCR 页、日志页和设置页，不替代 Web 工作台 UI 规范，也不替代三端统一界面原则。

如果要判断 WPF、Web、后端管理视角之间共同的产品气质，先看 [`product-interface-principles.md`](./product-interface-principles.md)。

## 3. WPF 助手一句话定义

`WPF 本地助手 UI = 紧凑、清爽、低打扰、适合后台长期运行的小窗口工具界面。`

它不追求第一眼惊艳，而追求：

- 信息清晰
- 操作稳定
- 小窗口可用
- 长时间挂后台不烦
- 与 Web 工作台保持同一产品气质
- 后续容易扩展

WPF 更偏“本地识别助手”，不是完整数据工作台。

---

## 4. 当前产品语境

WPF 本地助手负责：

- 登录/注册小窗口
- UID 初始化入口
- 后台识别状态
- 手动识别入口
- 截图/OCR 诊断
- 日志和设置

WPF 不负责：

- 深度声骸数据管理
- 大型统计图表
- 预测分析工作台
- 全屏管理后台
- 面向开发者的调试控制台

因此 WPF UI 默认应更接近：

- 桌面工具
- 本地助手
- 低噪音后台软件
- 小而清楚的状态面板

而不是：

- 营销页
- 游戏启动器
- 娱乐型面板
- 大屏后台管理系统
- 视觉实验场

## 5. 核心设计原则

### 5.1 信息优先于装饰

视觉第一职责是帮助用户理解账号、UID、识别状态、最近结果和错误原因。

质量感来自：

- 字重
- 间距
- 对齐
- 留白
- 信息分组
- 状态层级

而不是来自：

- 大面积渐变
- 重阴影
- 发光
- 装饰背景

### 5.2 小窗口优先

WPF 本地助手默认不是全屏软件。

设计时必须优先保证：

- `430x420` 左右登录窗口可用
- `960x680` 左右主窗口可用
- `820x560` 最小窗口核心操作仍可访问
- 125%/150% DPI 下文字不截断

### 5.3 主路径低打扰

WPF 的日常主路径是后台挂载和状态查看，不是复杂编辑。

因此：

- 登录窗口只做登录/注册
- 首页只展示关键状态和 UID 初始化
- 左侧导航只放助手功能
- 深度数据管理留给 Web

### 5.4 视觉系统优先于单页特效

新样式优先进入共享 XAML 样式字典。

不要为某个页面单独发明一套按钮、卡片、状态标签和颜色。

---

## 6. 明确允许与禁止

允许的整体气质：

- 清爽
- 专业
- 克制
- 轻量
- 有桌面工具感
- 有一点游戏数据工具的活力，但不花

明确禁止：

- 玻璃拟态
- 重模糊
- 霓虹发光
- 大面积炫目渐变背景
- 过度圆角
- 为了高级感堆大阴影
- 单页专属花哨特效
- 登录页或助手页做成营销 hero

## 7. WPF 组件规则

### 7.1 登录窗口

登录窗口只保留：

- 品牌标题
- 简短说明
- 用户名
- 密码
- 登录
- 注册
- 表单底部状态提示

登录窗口不放：

- 游戏 UID 选择
- UID 初始化
- 后端地址
- 调试配置
- 主功能 tab

### 7.2 主窗口导航

左侧导航只放助手功能：

- 首页
- 识别
- 截图/OCR
- 日志
- 设置

不放：

- 连接
- 登录
- 游戏账号
- 后端地址

### 7.3 首页

首页负责展示：

- 当前系统账号
- 当前 UID
- 当前识别状态
- UID 未绑定时的初始化入口

首页不负责：

- 深度统计
- 声骸列表管理
- 预测分析

### 7.4 按钮

按钮应有清晰层级：

- 主按钮：登录、保存 UID、提交关键动作
- 次按钮：注册、创建会话等低一级动作
- 谨慎按钮：回滚、撤销等动作
- 导航按钮：左侧 tab

规则：

- 按钮使用统一圆角和高度
- 同一组按钮视觉强度一致
- 不使用默认方形系统按钮
- disabled、hover、pressed 状态必须完整

### 7.5 状态标签

状态标签只用于表达真实状态：

- 当前账号
- 当前 UID
- 识别状态
- 连接状态
- 错误/警告/成功

状态标签不作为装饰点缀。

## 8. Token 与样式规则

新增视觉角色时优先：

1. 复用现有样式。
2. 扩展共享样式字典。
3. 再考虑局部样式。

WPF 当前共享样式 owner：

- `Styles/Colors.xaml`
- `Styles/Controls.xaml`
- `Styles/Layout.xaml`

规则：

- 颜色使用语义角色，而不是页面随手硬编码。
- 圆角、padding、边框强度收敛到有限档位。
- 状态色要服务语义。
- 页面局部样式不能成为长期视觉事实。

### 8.1 WPF UI 复用规则

同类界面效果必须优先复用共享 XAML 资源。

规则：

- 同类按钮复用同一 Button Style。
- 同类状态标签复用同一 StatusChip 或等价共享样式。
- 同类输入框、分组容器、提示文案不在页面内重复写模板。
- 页面需要新样式时，先判断它是不是新的长期语义。
- 如果只是局部微调，优先通过参数、资源或布局解决，而不是复制一份样式。
- 不把大量重复 XAML 复制到多个页面。

---

## 9. 给 Codex 与后续协作者的默认约束

- 不为单页需要新增一次性视觉规则
- UI 修复仍要遵守 owner 边界
- 登录窗口继续保持纯登录/注册
- UID 初始化继续归属首页
- 如果方案明显偏离本文，应先确认
- 当前阶段优先做 UI 结构和质量重构，再继续堆新功能
