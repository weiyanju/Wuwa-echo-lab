# Web 工作台 UI 规范

## 1. 文档定位

本文定义 `Wuwa` Vue Web 工作台的长期 UI 规范。

它只约束 Web 端的数据管理、统计、预测、评估、识别结果复核和账号/UID 状态展示，不替代 WPF 本地助手 UI 规范，也不替代三端统一界面原则。

如果要判断 WPF、Web 与未来界面的共同产品气质，先看 [`product-interface-principles.md`](./product-interface-principles.md)。

---

## 2. Web 工作台一句话定义

`Web 工作台 = 面向深度查看、管理、统计和分析的声骸数据界面。`

Web 应该比 WPF 承载更多信息，但仍然保持清晰、克制和可扫描。

它服务的是用户主动打开后深入处理数据的场景，而不是长期后台挂载。

---

## 3. 与 WPF 的分工

WPF 负责后台运行、窗口检测、本地截图、本地 OCR、快速提交识别结果、最近状态和诊断。

Web 负责声骸列表和详情、调谐记录管理、统计、预测、评估、识别快照复核、回滚和冲突处理。

规则：

- Web 不复制 WPF 的后台识别主链。
- WPF 不承接 Web 的完整数据管理工作台。
- 两端必须共享同一套系统账号、`GameAccount` 和 UID 心智。

---

## 4. 信息架构

Web 工作台默认信息层级：

1. 当前系统账号和当前 UID
2. 当前数据范围和筛选条件
3. 核心数据列表或分析结果
4. 详情、编辑、复核和回滚动作
5. 辅助统计、提示和诊断入口

规则：

- 当前 UID 必须始终容易确认。
- `GameAccount` 变更应影响整个工作台数据范围。
- 筛选、排序、分页状态应清晰可见。
- 识别快照、声骸数据、统计预测不能混成一个不可理解的大面板。

---

## 5. 页面类型

### 5.1 声骸列表页

应优先使用表格或密集列表。

必须支持：

- 当前 UID 范围
- 关键属性展示
- 筛选
- 排序
- 空状态
- 加载状态
- 错误状态

不应：

- 用大量装饰卡片替代表格
- 让用户必须滚动很远才能比较数据
- 隐藏关键字段导致无法判断声骸价值

### 5.2 声骸详情页

应展示基础信息、主属性、副词条、调谐记录、来源或识别快照、可回滚或可追溯信息。

规则：

- 编辑动作和危险动作必须分层。
- 预测和统计可以作为辅助区域，不抢基础数据主位置。

### 5.3 统计与预测页

应服务判断，而不是制造视觉噪音。

规则：

- 图表必须有明确标题、单位和解释。
- 关键结论应靠近图表。
- 模型评估和预测结果必须标明数据范围。
- 数据不足时明确提示，不假装给出可靠结论。

### 5.4 识别快照复核页

应展示：

- 识别时间
- 关联 UID
- snapshot 状态
- raw/normalized 关键字段
- 置信度
- duplicate/conflict/rejected 原因
- 回滚入口

规则：

- 冲突和低置信度不能用普通成功样式呈现。
- 回滚必须是谨慎动作。
- 用户应能理解“为什么没有写入正式数据”。

---

## 6. 布局与响应式

Web 首先服务桌面工作台，但不能在小屏完全崩坏。

桌面端规则：

- 左侧或顶部导航保持稳定。
- 主内容区优先用于数据和分析。
- 过滤器可以作为顶部条、侧栏或折叠面板。
- 表格和图表不放进过多嵌套卡片。

小屏规则：

- 核心状态和主要操作仍可访问。
- 表格可以转为分组列表。
- 筛选可以折叠。
- 文本不能溢出按钮、标签或卡片。

---

## 7. 数据密度

Web 可以比 WPF 更高密度，但高密度必须可扫描。

允许：

- 表格
- 分组列表
- 紧凑状态标签
- 可折叠详情
- 固定工具栏

避免：

- 大面积 hero
- 装饰型大卡片堆叠
- 信息很少但占据大屏的面板
- 为视觉留白牺牲数据比较效率

---

## 8. 组件规则

Web UI 必须优先复用组件和样式。

规则：

- 相同按钮层级复用同一按钮组件或 class。
- 相同状态标签复用同一状态组件或 class。
- 表格、筛选器、空状态、错误状态、加载状态应统一实现。
- API 状态展示不在每个页面重复写一套。
- 新增页面前先确认 `components/`、`composables/`、`services/` 是否已有可复用能力。

### 8.1 表格

表格应支持 loading、empty、error、selected、sorted、filtered。

字段较多时优先固定关键列、折叠次要字段、使用详情侧栏或详情页。

### 8.2 筛选器

筛选器应贴近数据列表，能清空，能显示当前生效条件，不默认占用过多高度。

### 8.3 图表

图表必须有明确数据范围、单位、空状态和数据不足状态，不只靠颜色表达含义。

### 8.4 表单

表单应分组，就近显示错误，明确保存状态，避免一次展示过多低频字段。

### 8.5 声骸工作台副词条录入矩阵

声骸工作台的副词条矩阵优先服务“快速录入当前声骸”，默认不展示“预测 xx%”“较基线 xx%”等研究指标；这些预测数据可以继续保留在状态、接口响应和统计/评估页面中，但不抢占录入主流程。

副词条档位值必须按类型显示单位：百分比类副词条显示 `%`，固定数值类副词条不显示 `%`；如果页面展示预测概率，概率仍按百分比显示。

副词条行在未录入、预测最高、已录入和 pending 状态之间切换时，应保持稳定行高、左侧信息区宽度、边框和高亮占位。长副词条名与“预测最高”等状态胶囊应保持同一行，胶囊不换行，标题可截断但不能挤压操作区。

声骸初始化配置区在 COST、套装或主词条候选数量变化时，应优先保持录入路径自然稳定。候选区不应通过固定大高度制造异常留白；如果数量变化会导致明显跳动，可使用短促、克制的真实内容高度过渡和按钮移动过渡缓和变化，同时保持 1C 等低候选数量场景紧凑。

### 8.6 通用控件图标

Web 工作台的通用控件图标优先使用 Iconoir 官方 SVG 素材，保持 24px 视图、1.5px 描边、圆端点和圆连接，并通过统一的 `ui-line-icon` mask 样式接入。新增刷新、勾选、关闭、展开、帮助、主题切换、面板控制等工具型图标时，应先查找官方 Iconoir 素材，不手写近似图形。

业务或品牌素材不纳入通用控件图标替换范围，例如历史面板最小化态的葫芦图标、favicon、声骸效果图和其他需要承载产品记忆或游戏语义的图片。

---

## 9. 状态与反馈

Web 重要流程必须覆盖：

- 加载中
- 保存中
- 保存成功
- 保存失败
- 权限不足
- UID 未绑定
- 当前 `GameAccount` locked
- 数据为空
- 数据不足以预测
- 识别结果冲突
- 回滚中
- 回滚成功或失败

错误文案应说明用户下一步能做什么。

## 11. 给 Codex 与后续协作者的默认约束

- Web 是深度工作台，不是 WPF 后台识别界面的复制品。
- 新大型 Web 能力不继续堆进 `App.vue`。
- 数据可读性优先于展示效果。
- 统计和预测必须标明数据范围和不足状态。
- Web UI 改动不能创造另一套账号、UID 或 `GameAccount` 心智。
