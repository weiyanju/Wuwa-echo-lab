# 评估页暗色主题 token 收敛实施记录

## 背景

在不改变当前产品视觉的前提下，按 `DESIGN.md` 与设计治理规范对评估页暗色主题做第一批语义 token 收敛。此次工作只处理已经在全局主题中定义、且值与用途完全一致的颜色，不引入新配色，也不扩大到数据可视化、模型状态色或仍存在多重语义的历史颜色。

## 实施范围

- `#e7eef4` 改为 `var(--ink-deep)`。
- `#a9bac7` 改为 `var(--charcoal)`。
- `#98aab7` 改为 `var(--steel)`。
- `#17232d` 改为 `var(--surface-soft)`。
- `#8dc3ff` 改为 `var(--primary-deep)`。
- 同步覆盖以上颜色在 `color-mix()`、渐变底色、边框和局部自定义属性中的等值引用。
- 保留 `#1d2a35`、模型强调色、图表节点色和其他尚无单一语义映射的颜色，避免为了降低未登记颜色数量而错误合并设计含义。

## 设计边界

- 以当前页面实现和 `DESIGN.md` 为基线，不重新配色。
- 仅复用 `controls.css` 暗色主题已存在的语义 token，没有修改 token 值。
- 迁移前后使用同一暗色评估页夹具，对外壳、面板、卡片、标题、辅助文本、弱化文本和摘要链接的计算样式逐项比对。
- 计算样式对象完全相等，前后全页截图字节数相等，确认没有视觉漂移。

## 回归保护

新增设计状态测试，要求评估页不再直接引用这五个已映射暗色值，并确认语义 token 的源值保持不变。该测试防止后续把历史色重新写回 feature CSS，或在未评审的情况下改动主题映射。

## 验证结果

- 针对性设计测试：6/6 通过。
- Web 全量测试：221/221 通过。
- Vite 生产构建：通过。
- 浏览器计算样式基线：完全一致。
- 浏览器前后截图字节数：完全一致。

## 后续原则

后续 token 整理继续按组件族逐批执行：先证明相同值具有相同语义，再迁移到既有 token；没有明确语义归属的颜色继续留在 feature CSS，不以审计数量为目标做机械替换。
