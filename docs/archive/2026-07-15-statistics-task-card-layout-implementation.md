# Statistics Task Card Layout Implementation

**Date:** 2026-07-15
**Scope:** 仅重排已有样本时的统计页；零样本初始化、工作台与评估页空状态不在本次实施范围内。

## 实施结果

- 移除统计页外层 `product-panel full-panel` 巨型卡片视觉，保留透明页面 owner 与区域级“统计诊断”说明。
- 将内容重排为两张同级任务卡：
  - “样本可信度”承接可信度结论、阶段标签、样本数量进度与完整阶段轴。
  - “副词条分布偏差”承接当前偏高、当前偏低与全部副词条发散图。
- 观察率和基线率继续使用 `%`，两者差值改用百分点 `pp`，例如 `+18.18pp`。
- 修复“当前偏低”的极值选择：从按绝对偏差排序的结果中取第一个负值，避免误选最接近零的负偏差。
- 深浅主题复用同一 DOM。860px 以下摘要纵向排列；680px 以下阶段轴与偏差图保留可访问的内部横向滚动，并使用细滚动条，不产生页面级横向溢出。

## 代码边界

- `StatisticsView.vue` 继续作为统计页面唯一布局 owner，没有新增 API、store 或跨页面状态。
- `presentation.js` 继续负责排序和阶段计算。
- `formatters.js` 新增 `formatSignedPercentagePoints`，模板不自行拼接单位。
- `statistics.css` 负责两张任务卡、深色映射和响应式，不引入新的全局视觉体系。
- `App.test.js` 与统计页专属测试同步迁移到新的任务卡 DOM/CSS owner。

## TDD 与回归证据

1. 百分点格式测试先失败，原因是 `formatSignedPercentagePoints` 尚未导出；最小实现后通过。
2. 两张任务卡结构测试先失败，原因是旧页面仍使用巨型外壳且模块归属相反；重排模板和 feature CSS 后通过。
3. 初次定向测试：33 passed，0 failed；补入中窄屏回归契约后最终为 34 passed，0 failed。
4. 完整前端测试首次发现两条 `App.test.js` 遗留选择器契约；确认根因后迁移旧 `.stats-diagnostic-panel` / `.stats-chart-card` 断言。独立复审随后发现 521–680px 内部滚动断点缺口，先以失败测试复现，再修复为 680px 启用内部滚动；最终 270 passed，0 failed。
5. 生产构建：`vite build --logLevel error`，exit code 0。

## 视觉验收

- 使用本地真实统计数据（286 条样本）检查 1280×720 浅色与深色主题。
- 检查 860×900：任务卡完整收敛为单列，页面无横向溢出，中等屏幕不出现无意义滚动条。
- 检查 600×900：页面 `scrollWidth` 与可视宽度同为 585px；阶段轴与偏差图分别在自身容器内滚动，右侧数据不再被裁切。
- 检查 520×900：页面无横向溢出；阶段轴和偏差图在自身容器内滚动，文字和关键指标保持可读。
- 实际页面确认偏差文案显示为 `+18.18pp`，当前偏低显示绝对偏差最大的负值。
