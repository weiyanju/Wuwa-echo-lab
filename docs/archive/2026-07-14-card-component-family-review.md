# Web 卡片组件家族审查（2026-07-14）

## 审查边界

本轮只盘点当前四页面基线中可见的容器、边框、圆角、嵌套和阴影，不修改 CSS。Bayes 路径、统计图表轨道、评估模型条和其他真实数据结构不按装饰卡片处理。

长期规则要求页面级容器使用 `20px - 24px` 圆角、中型卡片使用 `14px - 18px`、密集数据单元使用 `8px - 12px`，默认面板依赖边框和背景分层，阴影只用于浮层或真正脱离背景的控件。

## 已核验组件家族

| 家族 | 现状 | 结论 |
|---|---|---|
| 登录认证卡片 | `auth.css` 的 `.terminal-auth-card` 使用中型圆角、1px 边框和低强度阴影；它是居中的独立认证表面。 | 保留。层级职责明确，不构成卡片堆叠。 |
| 工作台同级主面板 | `controls.css` 的 `.product-panel` 与 `workspace.css` 的 `.gallery-panel` 均为 `24px` 页面级容器。浅色模式无阴影；暗色模式分别通过 `.app-shell.theme-dark .product-panel` 和 `.app-shell.theme-dark .gallery-panel` 得到 `0 18px 42px rgba(0, 0, 0, 0.24)`。 | 发现一处同组件家族的明暗层级不一致：页面内流式面板在暗色模式获得了仅适合浮层的明显阴影。 |
| 浮动历史面板 | `history.css` 的 `.floating-history-panel` 使用 `position: fixed`、较高层级、半透明背景、模糊和阴影；最小化状态明确取消阴影。 | 保留。它确实脱离页面流，阴影承担空间层级。 |
| 统计诊断与图表容器 | `statistics.css` 的 `.stats-diagnostic-panel` 为 `10px`，`.stats-chart-card` 和内部图表为 `8px`；暗色最终规则将这些容器阴影归零。 | 保留。它们是密集数据分组，不是装饰卡片。早期暗色阴影声明会被后续同等或更高层级规则覆盖，不形成最终视觉问题。 |
| 评估图表、模型和风险容器 | `evaluation.css` 使用 `8px - 12px` 密集容器圆角，并为暗色数据卡片取消阴影。 | 不列为装饰卡片问题。它们承载真实指标、模型比较或风险结构。 |
| 首次 UID 绑定卡片 | `uid-setup.css` 的 `.uid-setup-card` 是独立、居中的首次设置表面，使用 `28px` 圆角和明确阴影。 | 当前账号已绑定，运行态不可达；本轮不凭源码单独改造，留待首次绑定专项基线。 |

## 第一项局部建议：工作台暗色主面板去阴影

只调整工作台同级主面板：

- 当前：`.create-panel` 继承暗色 `.product-panel` 阴影，`.gallery-panel` 另外声明同值阴影；两块页面内流式容器同时浮起。
- 建议：仅在 `workspace.css` 中让暗色 `.create-panel` 和 `.gallery-panel` 使用 `box-shadow: none`，保留现有 24px 圆角、边框、渐变表面、间距和结构。
- 不影响：浮动历史面板、登录卡片、统计图表、评估模型容器、首次 UID 绑定卡片。

预期变化很小：暗色工作台由“两个浮起的大卡片”收敛为“两个安静的同级任务面板”，同时与浅色模式的层级策略对齐。

## 审批状态

用户确认当前阴影不明显，选择保持现状。本家族审查结束，不修改卡片 CSS；浮动历史面板和工作台两块同级主面板均保留当前阴影。
