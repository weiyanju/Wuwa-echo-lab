# 模型评估任务卡片布局实施记录

## 结果

- 模型评估页改为页面摘要和三个同级任务卡片，不再使用包住全部策略内容的巨型视觉卡片。
- 阅读顺序调整为核心回测、当前融合权重、子模型回测。
- 核心图表、融合权重项和子模型列表分别改为单边界内部结构。
- 子模型详情默认收起，并保持一次只展开一项。
- 深浅主题使用相同结构，响应式覆盖 1180px、860px 和 520px。
- 浏览器验收中发现列表裁切会影响外扩焦点环，已将 disclosure 焦点环收进按钮内部并补充回归测试。

## 代码边界

- `EvaluationView.vue` 负责页面摘要和模块编排。
- `EvaluationCoreBacktest.vue` 负责核心命中范围与校准摘要。
- `EvaluationOverview.vue` 负责融合权重和结论。
- `EvaluationBacktest.vue` 负责子模型诊断交互。
- `evaluation-layout.css` 负责页面任务卡片层级、内部扁平结构和响应式布局；文件保持在 260 行架构预算内。

## 验证

- `..\.tools\node\npm.cmd test`：通过，266/266 项测试成功。
- `..\.tools\node\npm.cmd run build`：通过，Vite 8.0.10 完成生产构建，78 个模块转换成功。
- 定向评估、架构和设计状态测试：通过，66/66 项测试成功。
- 1440 × 900 浅色与深色浏览器验收：三个任务卡片顺序、尺寸和间距一致，模块内部无重复完整卡片外壳。
- 1180px：融合权重为 3 + 2 排列，分隔线完整且页面无横向溢出。
- 860px：模块标题与右侧元数据以 16px 间距换行，状态 chips 左对齐且不覆盖。
- 520px：融合权重单列、Loss 列隐藏、五个 disclosure 均为 `tabIndex=0` 的原生按钮，页面无横向溢出，焦点环位于裁切壳内部。
- Markov 时间轴拖拽：`scrollLeft` 从 0 变化到 400；切换其他模型后 220ms 过渡结束仅保留一个展开详情，再次点击可全部收起。
- 暗色详情：Bayes、Markov、Cycle、Rule、Context 均沿用透明内部层，没有暗色模式专属的额外容器背景。
- 视觉基线：`docs/design-baselines/web/2026-07-15/evaluation-light.png`、`evaluation-dark.png`。
- 截图环境：从 1440 × 900 CSS 视口采集；Windows DPR 1.5 下应用内截图返回 1424px 内容区 JPEG 字节，保存前仅重新编码为真实 PNG，未修改页面内容。
- `git diff --check`：通过，无空白错误。

## 实施偏差与修正

- 原计划中的两条 `App.test.js` 断言仍锁定旧版默认展开状态；组件改为默认收起后同步更新为新的单展开契约。
- 浏览器验收新增了焦点环裁切回归测试与修复，这是 520px 可访问性验收直接发现的边界问题。

## 未改变范围

- 未修改模型评估 API、数据库、样本边界、命中率算法、融合权重算法或预测流程。
- 未为视觉验收伪造或写入评估数据。
