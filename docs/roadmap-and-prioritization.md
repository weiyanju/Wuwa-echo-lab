# 路线图与优先级规范

## 1. 文档定位

本文定义 `Wuwa` 当前阶段的长期路线主题与默认优先级判断规则。

它不是细粒度 backlog，而是以后面对多个方向竞争时，用来回答这些问题的长期基线：

- 先做什么，后做什么
- 什么情况可以打断当前主线
- 什么类型的工作应该延后
- 架构整理什么时候应该让路，什么时候应该提升优先级

---

## 2. 当前阶段判断

当前仓库处于：

- 本地助手 MVP 后的规范化阶段
- Web 与后端已有基础能力
- WPF 本地助手正在从联调面板转向正式助手
- 项目管理、代码质量、UI 规范需要先收口

因此当前路线不按“大功能扩张期”管理，而按“规范化 + 核心链路打磨期”管理。

---

## 3. 当前阶段北极星

当前阶段的北极星是：

**把 Wuwa 收口成一个可信、低打扰、可持续开发的鸣潮声骸管理与本地识别助手。**

所有优先级判断默认回到这句话。

如果某项工作能明显增强下面任一项，它通常更值得优先做：

- 项目管理规范
- 数据可信
- 本地助手低打扰体验
- 后台低占用与 OCR 性能可控
- 截图/OCR/识别链路稳定性
- Web 深度分析价值
- 长期可维护性

---

## 4. 当前路线图主题

### 4.1 主题一：项目管理规范化

这是当前最高优先级。

包括：

- 长期文档体系
- 架构 owner 边界
- 工程质量规则
- 问题修复分流
- API 与数据契约
- 安全、隐私与数据边界
- UI 规范
- 版本与发布口径

在这些规范未清晰前，不应继续大规模堆新功能。

### 4.2 主题二：代码质量收口

包括：

- WPF `MainWindow.xaml.cs` 变薄
- WPF core 模块落地
- Vue `App.vue` 后续拆分
- 后端 API owner 清晰
- 测试覆盖关键契约

### 4.3 主题三：UI 界面重构

包括：

- 登录窗口精简
- 主窗口首页稳定
- Web 顶部导航、工作台摘要区与圆角体系规范
- Web 工作台规范化
- 按钮、状态、卡片样式统一
- Web 与 WPF 产品气质统一

### 4.4 主题四：API 契约、安全隐私与数据边界

包括：

- `GameAccount` 契约
- API response shape
- 识别快照字段稳定性
- 截图与 OCR 隐私边界
- 诊断日志边界
- 云端部署数据流边界

### 4.5 主题五：截图与窗口检测

包括：

- 游戏窗口发现
- 截图区域
- DPI 与分辨率适配
- 截图 hash
- 截图失败诊断

### 4.6 主题六：本地离线 OCR 与缓存

包括：

- OCR provider 接口
- fake OCR provider
- 本地 OCR 原型
- OCR 缓存
- OCR 队列
- OCR 耗时记录
- 字段置信度
- 低置信度保护

### 4.7 主题七：后台运行与性能控制

包括：

- 后台识别状态机
- 低频窗口检测
- 候选场景短时高频检测
- 失败退避
- OCR worker 单队列
- 缓存命中率
- 长时间运行内存观察
- 性能诊断日志

### 4.8 主题八：识别流水线与后端持久化

包括：

- recognition pipeline
- snapshot payload builder
- 去重
- 回滚
- 失败恢复
- 后端结构化持久化

### 4.9 主题九：诊断、设置、打包发布

包括：

- 诊断日志
- 设置持久化
- 后台开关
- 检测频率
- 打包安装
- 版本发布
- 未来云端迁移准备

---

## 5. 默认优先级顺序

在没有更强理由时，默认按以下顺序排序：

1. 项目管理和长期规范
2. 会影响数据可信或 UID 归属的问题
3. 会让 WPF 主路径不可用的问题
4. 会持续制造回归的结构问题
5. UI 结构和视觉一致性
6. API 契约、安全隐私和数据边界
7. 后台低占用、截图/OCR 性能和缓存
8. 截图、OCR、识别流水线新能力
9. 低频增强、实验性想法、技术栈探索

换句话说：

- `规范化` 高于 `继续堆功能`
- `数据可信` 高于 `预测花样`
- `WPF 日常入口` 高于 `Web 边缘功能`
- `本地 OCR 隐私边界` 高于 `云端 OCR 便利`

---

## 6. 什么情况可以打断当前主线

以下事项默认允许插队：

- 登录或注册无法使用
- UID 绑定或 `GameAccount` 归属错误
- WPF 无法启动
- 后端写入错误数据
- 识别结果不可回滚
- 截图或 OCR 会上传不该上传的数据
- 后台识别出现持续高 CPU、持续内存增长或 OCR 任务堆积
- API 字段变化会破坏 Web 或 WPF 主路径
- 日志、缓存或云端能力改变隐私边界
- 关键测试或构建失败
- UI 主路径严重不可用

---

## 7. 当前阶段应主动压低优先级的方向

以下方向不是永远不做，但当前不应主动抬高：

- 云端 OCR
- 跨平台桌面重写
- Tauri 替换 WPF
- GPUI 替换 WPF
- 移动端
- 团队协作
- 重型 SaaS 管理后台
- 游戏自动化操作
- AI 大段总结类功能

---

## 8. 新需求进入路线前的默认判断

一个新需求进入当前路线前，需要回答：

- 它服务当前核心用户吗？
- 它增强声骸管理、本地识别、数据可信或低打扰体验了吗？
- 它会不会造成长期后台占用、OCR 重复执行或任务堆积？
- 它会不会破坏本地 OCR 隐私边界？
- 它会不会破坏 API 与数据契约？
- 它会不会让 WPF 或 Vue 高吸力层变厚？
- 它是否能在当前架构内落地？
- 它需要哪些测试或验收？

回答不清时，默认先不进入当前路线。

---

## 9. 给 Codex 与后续协作者的默认约束

- 不因为新功能更显眼就压过规范化
- 不因为架构整理听起来抽象就忽视它
- 不因为 Tauri/GPUI 新鲜就打断 WPF 当前主线
- 不因为 Web 未来上云就默认改变 OCR 主路径
- 多个方向竞争时，先按本文判断优先级
