# 版本与发布规范

## 1. 文档定位

本文定义 `Wuwa` 长期使用的版本管理、发布准备和发布验证规则。

它不是某一轮发布说明，也不是一次性操作清单，而是以后每次准备发布版本时都应遵循的长期规则。

---

## 2. 当前仓库现实

当前项目还没有进入正式稳定发布线。

当前阶段定义为：

- `MVP / pre-release` 阶段
- 暂不承诺稳定 SemVer
- 暂不承诺公开自动更新通道
- 先把本地助手 MVP、项目规范、代码质量和 UI 质量收口
- 等 WPF 助手可安装、可登录、可后台识别、可提交、可诊断后，再进入正式版本线

---

## 3. 当前版本策略

在正式版本线建立前，允许使用阶段性版本号或内部里程碑：

- `0.1.0`
- `0.2.0`
- `m8`
- `m8.1`
- `pre-release`

规则：

- 不把当前阶段误称为稳定版本。
- 不承诺向后兼容，除非某个接口已经被明确写入 API 契约。
- 数据库 migration 仍需谨慎，因为本地已有数据可能来自当前开发环境。
- 一旦开始打包给真实用户使用，就必须收紧版本规则。

---

## 4. 进入正式版本线的条件

进入正式版本线前，至少应满足：

- WPF 可安装或可稳定启动
- 登录/注册稳定
- `GameAccount` 与 UID 初始化稳定
- 本地助手可低占用后台运行
- fake pipeline 已被真实截图/OCR pipeline 替代或明确标记
- 识别结果可提交、可去重、可回滚
- OCR 不阻塞 UI，且具备 hash 缓存、结果缓存和可观测耗时
- 后端数据持久化稳定
- Web 可查看和分析 WPF 写入的数据
- 诊断日志能解释主要失败原因
- README 写清运行方式
- 最低验证链可重复执行

满足后，再建立正式 `SemVer` 规则。

---

## 5. 未来 SemVer 规则

正式版本线建立后，使用：

```text
MAJOR.MINOR.PATCH
```

默认含义：

- `PATCH`：向后兼容的 bug 修复
- `MINOR`：向后兼容的新能力
- `MAJOR`：不兼容变化

不兼容变化包括：

- 破坏已有数据库兼容
- 改变核心 API 语义
- 需要用户手动迁移才能继续使用
- 移除已发布版本中的核心能力
- 改变截图/OCR 隐私边界

---

## 6. 发布前最低验证

当前 pre-release 阶段，准备交付给用户试用前至少应完成：

```powershell
dotnet run --project WuwaAssistant\WuwaAssistant.Tests\WuwaAssistant.Tests.csproj
dotnet build WuwaAssistant\WuwaAssistant.slnx
```

并按改动范围补充：

- 后端测试
- Vue 测试或构建
- WPF 启动探针
- OCR/截图手动验证

正式版本线建立后，应再补充：

- changelog
- release notes
- 安装包验证
- 更新通道验证
- 数据升级验证

---

## 7. Changelog 规则

当前仓库可暂不维护正式 `CHANGELOG.md`，但一旦开始对外发布，应建立根目录 `CHANGELOG.md`。

推荐结构：

```md
# Changelog

## [Unreleased]

### Added
### Changed
### Fixed
### Removed
### Internal

## [0.1.0] - YYYY-MM-DD
```

写作规则：

- 面向用户结果，而不是 commit 清单。
- 不把开发过程中的中间尝试写成发布结果。
- 内部重构只记录对发布理解有价值的内容。
- 涉及隐私、数据迁移、OCR、识别写入的变化必须写清。
- 涉及 API 字段、`GameAccount` 契约、截图上传、日志内容或云端数据流的变化必须写清。

---

## 8. Tag 与发布规则

正式版本线建立前：

- 默认不推正式 `vX.Y.Z` tag。
- 可以使用分支和 milestone 文档管理阶段进度。

正式版本线建立后：

- Git tag 使用 `vX.Y.Z`。
- 代码版本、release 标题、changelog 必须一致。
- 不覆盖已发布稳定 tag。
- 如果某版本已经对外发布，后续修复进入新版本。

---

## 9. 云端部署与发布关系

后期后端和 Web 会迁移到云服务器。

这类变化属于发布级重大主题，必须单独规划：

- 云端后端部署
- Web 前端部署
- 数据库迁移
- 用户账号与数据同步
- 本地 WPF 连接云端 API
- 隐私与截图/OCR 边界

云端部署不自动意味着云端 OCR。

---

## 10. 给 Codex 与后续协作者的默认约束

- 当前不要把 pre-release 当成稳定发布
- 不默认创建 tag
- 不默认推送发布
- 准备发布前先确认版本策略
- 涉及用户数据或 OCR 隐私边界时，不作为普通小版本处理
- 正式发布体系建立时，先更新本文
