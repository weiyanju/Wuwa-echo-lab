# Tethys System 首页设计方案

> 本文档沉淀 Web 首页 / 登录页方向。根目录 [`DESIGN.md`](../DESIGN.md) 定义当前视觉 token 与字体，Web 长期方向遵循 [`web-ui-design-system-v2.md`](./web-ui-design-system-v2.md)，本文补充入口场景规则。

## 1. 设计定位

`Tethys System / 泰缇斯枢纽` 首页是产品入口，不是登录后的工作台。

它的目标：

- 建立专业、可信、低噪音的声骸数据工具气质。
- 提供清晰的登录 / 注册入口。
- 在登录后引导 UID 绑定。
- 让用户理解产品服务于声骸管理、识别复核、调谐记录和副词条分析。

它不承担：

- 工作台内部导航。
- 统计 / 评估 / 识别复核入口。
- 当前 UID 状态。
- 假声骸数据展示。
- 登录后工作台 shell。

首页方向目前被认为是正确的，应继续保留“浅色终端风 + 工具型产品识别”。当前 2–4px 硬朗边角、1px 边框、蓝色主色和克制动效已经成为入口场景的识别特征，不需要为了与工作台统一而改成相同圆角，也不能继续扩展为完整代码编辑器克隆。

## 2. 核心视觉语言

### 2.1 浅色终端感

首页可以比工作台更有氛围。

允许：

- 浅灰或近白背景。
- 轻量点阵、细线或终端协议感背景。
- 蓝色协议标签。
- 等宽字体点缀。
- 1px 边框。
- 克制的启动感动效。

避免：

- 大面积营销插画。
- 毛玻璃堆叠。
- 重阴影。
- 大面积渐变。
- 假数据仪表盘。
- 深色编辑器式整页外壳。

### 2.2 圆角策略

首页不继承工作台的默认 12px 控件圆角，而是保留当前已经批准的入口语言：

- 登录框使用 `4px` 级硬朗圆角。
- 输入框、主按钮、协议标签和框内图标按钮使用 `2px` 级圆角。
- 所有边角仍需保持清楚的 1px 边界、稳定命中区域和一致的 focus-visible。
- 小标签和状态 pill 仅在语义需要时使用胶囊形。

首页可以比工作台更有入口仪式感。两者的一致性来自字体角色、Tethys 蓝、信息层级、线形图标和低噪音表面，不来自完全相同的圆角。

### 2.3 字体

中文、标题、正文、按钮和表单使用 `IBM Plex Sans SC`，回退到 `Noto Sans SC`、`Microsoft YaHei UI` 和系统字体。首页顶部使用蓝色圆环圆点图标与紧凑 `TETHYS` 字标；完整 `Tethys System / 泰缇斯枢纽` 名称仍可用于首页说明、加载和首次绑定等需要完整产品识别的入口场景。登录后的顶部导航继续使用短字标 `TETHYS`。

等宽字体只用于：

- 协议标签，例如 `ECHO ANALYSIS PROTOCOL`。
- 状态标签，例如 `SYSTEM.ONLINE`。
- 短 metadata。
- 局部命令行前缀装饰。

正文、标题、按钮、表单说明不应大面积使用等宽字体。

### 2.4 图标

通用控件图标应遵守 Web 工作台图标规范：

- 线形图标优先。
- 24px 视图。
- 1.5px 左右描边。
- 圆端点和圆连接。
- 颜色继承当前语义。

图标服务信息密度，不作为装饰物。

## 3. 页面结构

首页采用左右分栏：左侧产品介绍，右侧登录 / 注册表单。

结构目标：

- 宽屏下保持两栏稳定。
- 左侧承担产品气质和能力概览。
- 右侧承担认证任务。
- 视觉重心集中，不制造过大空白。
- 移动端可自然降级为上下堆叠。

### 3.1 顶部状态导航

顶部只保留全局入口信息。

可以展示：

- 蓝色圆环圆点图标与紧凑 `TETHYS` 字标。
- 轻量 Logo / 呼吸状态点。
- `SYSTEM.ONLINE` 这类产品状态。
- 主题切换、帮助或设置入口。

不展示：

- `声骸工作台`。
- `统计`。
- `评估`。
- `识别复核`。
- `未登录`。
- `UID 未绑定`。

这些属于登录后工作区或账号状态，不应在认证前首页暴露。

### 3.2 左侧产品介绍面板

左侧承担产品定位和能力概览。

建议结构：

- 顶部协议标签：`ECHO ANALYSIS PROTOCOL`。
- 主标题：清晰表达产品入口，例如“欢迎回家，漂泊者”。
- 简短说明文案。
- `2x2` 或紧凑能力网格。

能力网格只保留核心能力名：

- 历史调谐记录。
- 本地截图识别。
- 多 UID 独立管理。
- 副词条预测面板。

每个能力项使用线形图标 + 短文本，不展示假统计值、假表格或内部工作台截图。

### 3.3 右侧认证卡片

右侧是稳定的任务窗口，内部包含两个完整页面：

1. 登录 / 注册认证页。
2. 首次 UID 绑定页。

结构要求：

- 登录 / 注册切换时高度稳定。
- 输入错误贴近对应字段。
- 主按钮位置稳定。
- 登录成功且已有 UID 时直接进入工作台。
- 登录成功但没有 UID 时，只把登录框内部切换为首次 UID 绑定页；外层标题、能力列表、背景和两栏布局保持不变。
- 从 UID 初始化页返回登录后，未完成 UID 绑定的系统账户可用相同正确凭据再次从“创建档案”恢复到 UID 页。账户停用、凭据错误或已完成 UID 绑定时保持在认证表单；已完成账户仍需使用“终端登录”，页面不新增恢复卡片或额外步骤。
- UID 页顶部使用全宽、居中的单抬头“绑定 UID”，复用认证页活动页签的排版角色、下方间距和深色 1px 规则线；该抬头不可点击，不表达页签或步骤条，也不在内容区重复大标题。说明、字段和提示保持同一左基线。蓝色 BIND_AND_ENTER() 是唯一主操作；其下方使用居中的灰色文字按钮“返回登录”，完整语义为“退出当前账号并返回登录”，执行退出后反向切回认证页。
- 登录框外框在内部切换时保持位置、宽度、边框、底色和桌面端高度稳定，不使用卡片推进、步骤条或整页跳转。

表单风格：

- 输入框保持浅色、清楚边框和当前 2px 入口圆角。
- 主按钮使用蓝色。
- label 文案清楚，不为终端感牺牲可读性。
- 可以保留少量命令行语气，但不能影响本地化理解。
- UID 数字使用 Data 字体角色和 `tabular-nums`。

## 4. 动效

首页可以保留一条克制的“终端启动时间线”，但登录入口不能因为动效延迟而难用。

允许：

- 协议标签短暂出现。
- 标题或关键文案轻量淡入。
- 左侧能力网格和右侧表单快速进入。
- 状态点轻微呼吸。
- 登录框内部认证页与 UID 页使用 16px 以内的方向性位移和淡入淡出。

主标题与认证入口遵守以下时序规则：

- 主标题打字效果必须按完整 Unicode 字素推进，不得通过连续 `width`、`max-width`、`clip-path` 或 `overflow` 裁切整段文字。
- 逐字动画开始前必须按完整标题准备最终字体字形；若字体准备失败或超过 180ms，直接显示完整标题和认证卡片，不带着 fallback 字体播放。
- 蓝色光标使用独立行内元素跟随当前文字末端，不以标题容器边框模拟。
- 桌面端认证卡片等待标题完成后再进入；等待期间不能进入焦点顺序、指针命中区域或无障碍树。
- 减少动态效果、520px 及以下窄屏和后台页面直接显示完整标题与认证卡片。

避免：

- 长时间打字机动画。
- 阻塞登录表单可见性。
- 大面积位移动画。
- 登录框外框移动、缩放或尺寸补间。
- 弹性、bounce 或过强视差。

所有动画都必须提供 `prefers-reduced-motion: reduce` 降级。

## 5. 响应式策略

桌面端优先完成首页设计完整性。

窄屏策略：

- 左右分栏降级为上下堆叠。
- 取消强制大留白。
- 两侧容器宽度为 `100%`。
- 能力网格允许自然换行。
- 表单卡片取消不必要的最小高度。
- 文本不得溢出按钮、标签或卡片。

当前阶段如果未计划移动端精修，可以先保证不崩坏，不为了移动端提前牺牲桌面信息结构。

## 6. 与工作台的关系

首页和工作台共享产品气质，但不是同一个页面模型。

首页可以：

- 更有入口仪式感。
- 使用终端协议标签。
- 使用更明显的产品标题。
- 用少量氛围元素建立记忆点。

工作台应该：

- 更高信息密度。
- 更少氛围装饰。
- 更强调录入、扫读和状态反馈。
- 保持当前圆角工具型基础。

不要把首页终端氛围直接扩展成工作台的完整 IDE Shell。

## 7. Vue 组件拆分建议

后续工程落地时，建议按现有项目结构和 ownership 拆分，不另起框架。

示例方向：

```text
views/Home/TerminalHome.vue
components/Layout/TerminalNavbar.vue
components/Home/FeatureMatrix.vue
components/Auth/OperatorAuthCard.vue
components/UI/BaseTerminalInput.vue
components/UI/BaseTerminalButton.vue
```

职责说明：

- `TerminalHome.vue`：首页主容器，处理分栏布局和页面级动效。
- `TerminalNavbar.vue`：顶部品牌与状态导航。
- `FeatureMatrix.vue`：左侧能力网格。
- `OperatorAuthCard.vue`：右侧登录 / 注册表单。
- `BaseTerminalInput.vue`：复用输入框样式。
- `BaseTerminalButton.vue`：复用主按钮样式。

实际文件位置应服从当前仓库已有架构。

## 8. 与长期 UI 规范的关系

本文档服务于 Web 首页，不替代：

- `docs/product-interface-principles.md`
- `DESIGN.md`
- `docs/web-ui-design-system-v2.md`
- `docs/web-workbench-ui-guidelines.md`
- `docs/security-privacy-and-data-boundaries.md`

首页必须遵守：

- 不展示未登录状态不可用的工作台内部导航。
- 不创造新的账号、UID 或 `GameAccount` 心智。
- 不展示假声骸数据。
- 不使用营销式 hero。
- 不用大面积视觉特效牺牲可读性。
- 登录后先绑定 UID，再进入工作台。
- 首次 UID 绑定只改变登录框内部页面；后续新增和切换 UID 仍归属登录后的账号菜单。

## 9. 验收清单

首页改动应满足：

- 首页顶部保留蓝色圆环圆点图标与紧凑 `TETHYS` 识别。
- 不把入口场景的完整品牌文案复制回登录后的紧凑顶部导航。
- 登录 / 注册路径清楚。
- 无 UID 时外层登录页保持不变，只有登录框内部切换到绑定页。
- 首次 UID 绑定页使用不可点击的全宽单抬头“绑定 UID”，不显示标题区返回图标；“返回登录”位于绑定主按钮下方，并在退出当前账号后返回认证页。
- 不暴露工作台内部模块。
- 不展示假数据。
- 与 V2.1 共享蓝色主色、字体层级和浅色工具感，同时保留本文定义的入口圆角。
- 不把 VS Code 客户端或完整 IDE Shell 带入首页。
- 标题动画任意帧只显示完整字素，认证卡片在标题完成前不可交互，完成后立即可用。
- 窄屏无明显横向溢出、文字裁切或控件重叠。
