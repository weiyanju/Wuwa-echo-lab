# Wuwa Echo Terminal 首页设计方案

> 前端 UI 重构优先级：本文档是首页方向沉淀；新的全局前端 UI 设计系统以 [`web-ui-design-system-v2.md`](./web-ui-design-system-v2.md) 为最高优先级。首页落地时应遵循 V2.0 中“首页与工作台的关系”：首页只承载产品介绍、登录/注册和绑定 UID 引导，不提前暴露完整工作台 shell。

## 1. 设计定位与愿景

`Wuwa Echo Terminal`（鸣潮声骸终端）首页的定位是一个“产品介绍 + 登录/注册一体化的硬核数据终端”。

它的目标用户是需要深度管理海量声骸、记录调谐数据以及依赖副词条预测面板的高阶《鸣潮》玩家。

在整体气质上，首页严格坚守“清晰、克制、专业、低噪音”的原则。设计应摒弃传统 SaaS 软件的营销感，例如大面积插画、沉重卡片底托、复杂毛玻璃和重阴影；转而以现代数据工具与代码编辑器式的精确界面语言，打造具有“极客工程感”与“沉浸式终端”氛围的入口页。

首页不承载未登录态不可用的工作台内部导航，也不提前暴露统计、评估、识别复核、UID 状态等工作区信息。它只负责建立产品气质、说明核心能力，并提供清晰的登录/注册入口。

## 2. 核心视觉语言

### 2.1 极简底色与点阵背景

页面摒弃纯色或大面积渐变背景，采用浅灰背景 `#fafafa`，叠加 `24px * 24px` 的微弱点阵纹理：

```css
rgba(0, 0, 0, 0.05)
```

点阵背景可配合 `60s` 极慢速背景平移，营造后台数据持续流动的“在线感”，但不能干扰前景阅读。

### 2.2 绝对扁平化与微边框

页面去除大阴影和毛玻璃效果。卡片、输入框和分区通过极细的 `1px` 浅灰边框划分界限。

圆角应极限收敛：

- 卡片：`16px`
- 输入框 / 按钮：`6px`
- 图标框：可取消圆角，保持更硬朗的线性结构

整体视觉应呈现“手术刀般”的锋利感。

### 2.3 等宽字体点缀

局部标签使用 `ui-monospace` 等宽字体栈，增强命令行工具的心智暗示。

适用位置包括：

- 副标题：`ECHO ANALYSIS PROTOCOL`
- 状态栏：`SYSTEM.ONLINE`
- 表单 label 前缀：`>`

正文、标题、按钮、普通表单内容仍使用项目默认 UI 字体，优先保证中文可读性。

### 2.4 官方规范级线形图标

通用控件图标遵循项目 Web 工作台图标规范：

- `24px` 视图
- `1.5px` 描边
- 圆端点与圆连接
- 线形图标优先
- 不为图标增加装饰性底托或背景

图标应作为信息密度的一部分，而不是装饰物。

## 3. 页面布局与架构

首页采用左右分栏结构：左侧为产品终端介绍面板，右侧为登录/注册一体化操作员表单。

布局应避免“孤岛效应”，在宽屏下保持视觉重心集中；容器宽度、间距可随视口做适度响应，但正文和控件字号不应过度流式缩放。

### 3.1 顶部状态导航栏

顶部只保留全局入口信息，不暴露工作区内部结构。

构成：

- 左侧：品牌名与呼吸灯 Logo
- 右侧：系统在线状态指示器，例如 `SYSTEM.ONLINE`
- 可选：主题切换、设置或帮助图标按钮

顶部不展示：

- `声骸工作台`
- `统计`
- `评估`
- `识别复核`
- `未登录`
- `UID 未绑定`

原因是这些属于工作区状态或内部模块信息，不应在认证前首页暴露。

### 3.2 左侧：流式终端介绍面板

左侧承担产品定位与能力概览。

视觉结构：

- 顶部协议标签：`ECHO ANALYSIS PROTOCOL`
- 主标题：`欢迎回家，漂泊者`
- 简短说明文案
- `2x2` 极简特性网格

视觉锚点：

- 可使用主题色小标记或细线作为协议锚点
- 不使用过强的装饰性粗边条
- 左右两栏顶部使用 `align-items: flex-start` 保持基线对齐

特性网格只保留核心能力名，避免冗余描述：

- 历史调谐记录
- 本地截图识别
- 多账号独立管理
- 副词条预测面板

每个能力项使用线形图标 + 简短文字，不展示假数据、统计值或内部表格。

### 3.3 右侧：模块化操作员表单

右侧为认证卡片，包含登录和注册两个模式。

结构要求：

- 卡片设定 `min-height: 480px`
- 登录 / 注册 tab 切换时页面高度保持稳定
- 主按钮通过 `margin-top: auto` 推至底部
- 错误信息贴近对应输入框，并明确告诉用户下一步能做什么

表单风格：

- label 使用 `>` 命令行前缀
- 输入框保持纯平浅灰质感
- 主按钮可采用终端风格文案，例如 `EXECUTE_LOGIN()`
- 若实际可读性或本地化体验不佳，可改为更直白的“登录进入”

登录成功后的下一步不是直接展示工作台数据，而是进入 UID 绑定流程。

## 4. 动效编排

首页舍弃杂乱过渡动画，只保留一条克制的“终端启动时间轴”。

建议节奏：

1. `0.1s`：左上角 `[ ECHO ANALYSIS PROTOCOL ]` 蓝色协议标识率先闪现。
2. `0.3s - 1.1s`：触发打字机动画，匀速敲出“欢迎回家，漂泊者”，耗时约 `0.8s`。
3. `1.1s`：打字机结束，句尾保留持续闪烁的终端光标。
4. `1.1s` 后：左侧功能网格与右侧表单同时、迅速地由下往上浮现。

这条编排应服务于“终端启动”的仪式感，同时保证登录入口不会因动画延迟过高而影响可用性。

所有动画都必须提供 `prefers-reduced-motion: reduce` 降级策略。

## 5. 响应式与降级策略

断点建议：

```css
@media (max-width: 1024px) {
  /* 左右分栏降级为上下堆叠 */
}
```

窄屏策略：

- 左右分栏降级为上下堆叠
- 取消强制居中与大面积留白
- 两侧容器宽度设为 `100%`
- 特性网格解除强制单行限制，允许文本自然折行
- 表单卡片解除最小高度限制，让空间更紧凑

当前阶段如未计划移动端适配，可先保证桌面端设计完整，避免为了移动端提前牺牲桌面信息结构。

## 6. Vue 组件拆分建议

后续工程落地时，建议按以下结构拆分组件：

```text
views/Home/TerminalHome.vue
components/Layout/TerminalNavbar.vue
components/Home/FeatureMatrix.vue
components/Auth/OperatorAuthCard.vue
components/UI/BaseTerminalInput.vue
components/UI/BaseTerminalButton.vue
```

职责说明：

- `views/Home/TerminalHome.vue`：页面主容器，处理流式布局与核心动画挂载。
- `components/Layout/TerminalNavbar.vue`：顶部带呼吸状态灯的导航组件。
- `components/Home/FeatureMatrix.vue`：左侧 `2x2` 线框图标网格组件。
- `components/Auth/OperatorAuthCard.vue`：右侧认证卡片，包含登录/注册 tab 状态机逻辑。
- `components/UI/BaseTerminalInput.vue`：封装带 `>` 前缀、纯平浅灰质感的底层输入框。
- `components/UI/BaseTerminalButton.vue`：封装带硬朗交互反馈的主题色按钮组件。

## 7. 与项目长期 UI 规范的关系

本设计文档服务于 Web 首页，不替代以下长期规范：

- `docs/product-interface-principles.md`
- `docs/web-workbench-ui-guidelines.md`
- `docs/security-privacy-and-data-boundaries.md`

首页可以比工作台更具终端入口气质，但仍需遵守以下原则：

- 不展示未登录态不可用的工作台内部导航
- 不创造新的账号、UID 或 GameAccount 心智
- 不展示假声骸数据
- 不使用营销式英雄区
- 不使用大面积视觉特效牺牲可读性
- 登录后先绑定 UID，再进入工作台
