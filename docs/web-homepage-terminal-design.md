# Tethys System 首页设计方案

> 本文档沉淀 Web 首页 / 登录页方向。根目录 [`DESIGN.md`](../DESIGN.md) 定义当前视觉 token 与字体，Web 长期方向遵循 [`web-ui-design-system-v2.md`](./web-ui-design-system-v2.md)，本文补充入口场景规则。

## 1. 设计定位

`Tethys System / 泰缇斯枢纽` 首页是产品入口，不是登录后的工作台。

它的目标：

- 建立专业、可信、低噪音的声骸数据工具气质。
- 提供清晰的登录 / 注册入口。
- 在登录后引导 UID 绑定。
- 让用户理解产品服务于声骸管理、识别复核、调谐记录和副词条分析。

它不承担：

- 工作台内部导航。
- 统计 / 评估 / 识别复核入口。
- 当前 UID 状态。
- 假声骸数据展示。
- 登录后工作台 shell。

首页方向目前被认为是正确的，应继续保留“浅色终端风 + 工具型产品识别”，但细节上需要和 V2.1 同步：不再强调极小圆角和完整代码编辑器克隆，而是保留终端氛围、1px 边框、蓝色主色和克制动效。

## 2. 核心视觉语言

### 2.1 浅色终端感

首页可以比工作台更有氛围。

允许：

- 浅灰或近白背景。
- 轻量点阵、细线或终端协议感背景。
- 蓝色协议标签。
- 等宽字体点缀。
- 1px 边框。
- 克制的启动感动效。

避免：

- 大面积营销插画。
- 毛玻璃堆叠。
- 重阴影。
- 大面积渐变。
- 假数据仪表盘。
- 深色编辑器式整页外壳。

### 2.2 圆角策略

旧文档中“输入框 / 按钮 6px、图标框可取消圆角”的硬朗设定不再作为默认目标。

首页应和 V2.1 保持一致：

- 页面级容器可使用 `20px - 24px`。
- 登录 / 注册卡片可使用 `18px - 24px`。
- 输入框和按钮建议 `10px - 14px`。
- 小标签和状态 pill 仅在语义需要时使用胶囊形。

首页可以比工作台稍有仪式感，但不能和工作台产生两个完全不同的产品。

### 2.3 字体

中文、标题、正文、按钮和表单使用 `IBM Plex Sans SC`，回退到 `Noto Sans SC`、`Microsoft YaHei UI` 和系统字体。完整 `Tethys System / 泰缇斯枢纽` 品牌可以在首页、加载和首次绑定场景出现；登录后的顶部导航改用短字标 `TETHYS`。

等宽字体只用于：

- 协议标签，例如 `ECHO ANALYSIS PROTOCOL`。
- 状态标签，例如 `SYSTEM.ONLINE`。
- 短 metadata。
- 局部命令行前缀装饰。

正文、标题、按钮、表单说明不应大面积使用等宽字体。

### 2.4 图标

通用控件图标应遵守 Web 工作台图标规范：

- 线形图标优先。
- 24px 视图。
- 1.5px 左右描边。
- 圆端点和圆连接。
- 颜色继承当前语义。

图标服务信息密度，不作为装饰物。

## 3. 页面结构

首页采用左右分栏：左侧产品介绍，右侧登录 / 注册表单。

结构目标：

- 宽屏下保持两栏稳定。
- 左侧承担产品气质和能力概览。
- 右侧承担认证任务。
- 视觉重心集中，不制造过大空白。
- 移动端可自然降级为上下堆叠。

### 3.1 顶部状态导航

顶部只保留全局入口信息。

可以展示：

- 品牌名。
- 轻量 Logo / 呼吸状态点。
- `SYSTEM.ONLINE` 这类产品状态。
- 主题切换、帮助或设置入口。

不展示：

- `声骸工作台`。
- `统计`。
- `评估`。
- `识别复核`。
- `未登录`。
- `UID 未绑定`。

这些属于登录后工作区或账号状态，不应在认证前首页暴露。

### 3.2 左侧产品介绍面板

左侧承担产品定位和能力概览。

建议结构：

- 顶部协议标签：`ECHO ANALYSIS PROTOCOL`。
- 主标题：清晰表达产品入口，例如“欢迎回家，漂泊者”。
- 简短说明文案。
- `2x2` 或紧凑能力网格。

能力网格只保留核心能力名：

- 历史调谐记录。
- 本地截图识别。
- 多 UID 独立管理。
- 副词条预测面板。

每个能力项使用线形图标 + 短文本，不展示假统计值、假表格或内部工作台截图。

### 3.3 右侧认证卡片

右侧是登录 / 注册一体化表单。

结构要求：

- 登录 / 注册切换时高度稳定。
- 输入错误贴近对应字段。
- 主按钮位置稳定。
- 登录成功后进入 UID 绑定流程，再进入工作台。

表单风格：

- 输入框保持浅色、清楚边框和足够圆角。
- 主按钮使用蓝色。
- label 文案清楚，不为终端感牺牲可读性。
- 可以保留少量命令行语气，但不能影响本地化理解。

## 4. 动效

首页可以保留一条克制的“终端启动时间线”，但登录入口不能因为动效延迟而难用。

允许：

- 协议标签短暂出现。
- 标题或关键文案轻量淡入。
- 左侧能力网格和右侧表单快速进入。
- 状态点轻微呼吸。

避免：

- 长时间打字机动画。
- 阻塞登录表单可见性。
- 大面积位移动画。
- 弹性、bounce 或过强视差。

所有动画都必须提供 `prefers-reduced-motion: reduce` 降级。

## 5. 响应式策略

桌面端优先完成首页设计完整性。

窄屏策略：

- 左右分栏降级为上下堆叠。
- 取消强制大留白。
- 两侧容器宽度为 `100%`。
- 能力网格允许自然换行。
- 表单卡片取消不必要的最小高度。
- 文本不得溢出按钮、标签或卡片。

当前阶段如果未计划移动端精修，可以先保证不崩坏，不为了移动端提前牺牲桌面信息结构。

## 6. 与工作台的关系

首页和工作台共享产品气质，但不是同一个页面模型。

首页可以：

- 更有入口仪式感。
- 使用终端协议标签。
- 使用更明显的产品标题。
- 用少量氛围元素建立记忆点。

工作台应该：

- 更高信息密度。
- 更少氛围装饰。
- 更强调录入、扫读和状态反馈。
- 保持当前圆角工具型基础。

不要把首页终端氛围直接扩展成工作台的完整 IDE Shell。

## 7. Vue 组件拆分建议

后续工程落地时，建议按现有项目结构和 ownership 拆分，不另起框架。

示例方向：

```text
views/Home/TerminalHome.vue
components/Layout/TerminalNavbar.vue
components/Home/FeatureMatrix.vue
components/Auth/OperatorAuthCard.vue
components/UI/BaseTerminalInput.vue
components/UI/BaseTerminalButton.vue
```

职责说明：

- `TerminalHome.vue`：首页主容器，处理分栏布局和页面级动效。
- `TerminalNavbar.vue`：顶部品牌与状态导航。
- `FeatureMatrix.vue`：左侧能力网格。
- `OperatorAuthCard.vue`：右侧登录 / 注册表单。
- `BaseTerminalInput.vue`：复用输入框样式。
- `BaseTerminalButton.vue`：复用主按钮样式。

实际文件位置应服从当前仓库已有架构。

## 8. 与长期 UI 规范的关系

本文档服务于 Web 首页，不替代：

- `docs/product-interface-principles.md`
- `DESIGN.md`
- `docs/web-ui-design-system-v2.md`
- `docs/web-workbench-ui-guidelines.md`
- `docs/security-privacy-and-data-boundaries.md`

首页必须遵守：

- 不展示未登录状态不可用的工作台内部导航。
- 不创造新的账号、UID 或 `GameAccount` 心智。
- 不展示假声骸数据。
- 不使用营销式 hero。
- 不用大面积视觉特效牺牲可读性。
- 登录后先绑定 UID，再进入工作台。

## 9. 验收清单

首页改动应满足：

- 保留 `Tethys System / 泰缇斯枢纽` 识别。
- 不把入口场景的完整品牌文案复制回登录后的紧凑顶部导航。
- 登录 / 注册路径清楚。
- 不暴露工作台内部模块。
- 不展示假数据。
- 与 V2.1 的圆角、蓝色主色、浅色工具感一致。
- 不把 VS Code 客户端或完整 IDE Shell 带入首页。
- 窄屏无明显横向溢出、文字裁切或控件重叠。
